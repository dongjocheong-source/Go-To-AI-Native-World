Subagent vs Agent team 완벽 비교 가이드

둘 다 작업을 병렬화하지만 아키텍처가 다르다. Subagent는 세션 내에서 실행되고 결과를 주 컨텍스트에 보고하는 반면, Agent team은 서로 독립적인 Claude Code 세션들이 직접 소통하며 협업한다.

Overview

핵심 정의

둘 다 작업을 병렬화하지만 통신 구조가 다르다 — 중앙 집중식이냐 분산식이냐.

Subagent

Main ← 결과 보고

세션 내에서 실행되고, 결과는 주 컨텍스트에만 보고된다. 주 에이전트가 모든 작업을 관리하는 중앙 집중식 구조다.

Agent team

팀원 ↔ 팀원 직접 소통

서로 독립적인 Claude Code 세션들이다. 공유 작업 목록을 두고 팀원끼리 직접 메시지를 주고받으며 스스로 조정한다.

Deep Dive

Subagent중앙 집중식 워커

세션 내에서 실행되고 결과는 주 컨텍스트에 보고된다.

1
독립적이지만 제한적인 컨텍스트자신만의 컨텍스트 윈도우를 갖지만, 결과는 호출자(주 에이전트)에게만 돌아간다.
2
단방향 통신주 에이전트에게만 결과를 보고한다 — 서로 대화하지 않는다.
3
토큰 효율적결과가 주 컨텍스트로 요약되어 돌아오므로 메인 메모리를 절약한다.
작동 방식
  1. Main Agent가 Subagent 1·2·3을 각각 독립 컨텍스트로 생성
  2. 각 Subagent가 자신의 작업을 완료하고 결과만 반환
  3. Main Agent가 모든 결과를 수집하고 조정
완료된 작업의 결과만 필요 병렬 처리로 속도 향상 필요 파일 검토, 작업 분할 필요 토큰 절약 필수
Deep Dive

Agent team분산식 협업

서로 독립적인 Claude Code 세션들이다.

1
완전한 자율성각 팀원이 자신만의 컨텍스트 윈도우와 완전히 독립적인 세션을 갖는다.
2
양방향 통신팀원끼리 서로 직접 메시지를 주고받는다.
3
분산식 조정공유 작업 목록을 두고 스스로 조정한다 — 각자가 독립적 메모리를 필요로 한다.
작동 방식
  1. Agent 1·2·3이 각각 독립 컨텍스트와 독립 세션으로 시작
  2. 팀원들과 자유롭게 메시지 교환
  3. 공유 작업 목록으로 서로 조정
협력이 중요한 복잡한 작업 팀원 간 상호작용 필요 각자 다른 전문성 필요 토큰 비용이 문제 아닐 때
Use Cases

실제 시나리오별 선택

시나리오 01 대규모 코드 베이스 검토
Subagent

상황: 10,000개 파일을 검토해야 하고 병렬 처리가 필요하다.

파일 검토는 독립적 작업메인이 모든 결과 조정병렬 처리로 속도 향상토큰 효율적
Main Reviewer ├─ Code Analyzer Subagent (파일 1-100) ├─ Security Analyzer Subagent (파일 101-200) ├─ Performance Analyzer Subagent (파일 201-300) └─ Style Analyzer Subagent (파일 301-400) → 모든 분석 결과를 Main이 종합
시나리오 02 다중 팀 프로젝트 개발
Agent team

상황: 프론트엔드, 백엔드, 데이터베이스 팀이 동시에 개발한다.

팀원 간 상호작용 필수설계 협의 필요API 스펙 협상 필요실시간 소통 중요
Frontend Agent ↔ Backend Agent — API 스펙 논의 Backend Agent ↔ Database Agent — 스키마 논의 → 셋이 직접 메시지를 주고받으며 조정
시나리오 03 문서 분석 및 요약
Subagent

상황: 계약서 100개를 분석하고 요약해야 한다.

각 문서는 독립적 분석병렬 처리 가능메인이 최종 요약팀원 간 협력 불필요
Contract Analyzer (Main) ├─ Subagent 1~5: 계약서를 20개씩 나누어 분석 → 메인이 모든 분석 결과를 종합
시나리오 04 AI 사업 제안서 작성
Agent team

상황: 마케팅, 기술, 재무 팀이 함께 제안서를 작성한다.

각 팀의 관점 필요팀원 간 협력 필수예산 · 일정 협의 필요지속적 상호작용
Marketing Agent ↔ Technical Agent — 기술 요구사항 협의 Marketing Agent ↔ Finance Agent — 마케팅 예산 협의 Technical Agent ↔ Finance Agent — 개발 일정 협의
Cost vs Value

비용-효과 비교

작업 규모: 100개 문서 분석 기준.

Subagent 방식

토큰 사용 낮음

Main Agent가 100개 결과를 조정하고, 10개 Subagent가 각 10개 문서씩 담당한다. 결과만 반환하므로 토큰 사용이 낮다.

Agent team 방식

토큰 사용 높음

5명의 Agent가 함께 일하며 각자 독립 세션을 유지한다. 전체 상황을 서로 파악해야 하므로 토큰 사용이 높다.

핵심 — 같은 규모의 작업이라도 팀원 간 상호작용이 필요 없다면 Subagent가 훨씬 경제적이다. 협업이 결과물의 질을 좌우한다면 Agent team의 추가 비용이 정당화된다.

  • 병렬 처리가 필요한가?
  • 토큰 효율이 중요한가?
  • 최종 결과 조정만 필요한가?
모두 YES → Subagent 사용
Agent team 체크리스트
  • 팀원 간 상호작용이 필수인가?
  • 실시간 협력이 필요한가?
  • 각 팀원이 독립적 역할을 하는가?
  • 토큰 비용이 문제 아닌가?
하나 이상 YES → Agent team 사용

Subagent 베스트 프랙티스

01
명확한 작업 분할각 Subagent의 책임을 명확히 하고 독립적 작업으로 설계한다.
02
효율적 결과 반환필요한 정보만, 요약형으로 반환하게 한다.
03
메인의 역할작업 분배, 결과 조정·통합, 최종 검증을 메인이 맡는다.

Agent team 베스트 프랙티스

01
명확한 역할 정의각 Agent의 전문성과 책임 범위를 분명히 한다.
02
효과적 커뮤니케이션규칙적인 체크인과 명확한 메시지를 유지한다.
03
공유 목표팀 전체의 목표를 공유하고 진행 상황을 투명하게 유지한다.
Summary

한 문장으로 정리하는 Subagent vs Agent team

결과만 필요하면 Subagent, 협업 과정 자체가 필요하면 Agent team.

01Subagent는 주 에이전트에게만 결과를 보고하는 중앙 집중식 병렬 워커다.
02Agent team은 완전히 독립적인 세션들이 직접 소통하며 스스로 조정하는 분산식 협업이다.
03토큰 비용은 Subagent가 훨씬 낮다 — Agent team은 각 팀원이 별도의 Claude 인스턴스이기 때문이다.
기억할 것 한 줄 — 결과만 궁금하면 Subagent, 논의 자체가 필요하면 Agent team.
