Embedded & 3rd Party

Claude 스킬을 두 개의 카테고리로 나눠 정리합니다. 각 스킬은 요약 · 세부 동작 · 적합한 상황 · 유의점(필요 시 설치법)으로 구성된 박스이며, 카테고리별 템플릿을 복사해 새 항목을 계속 추가할 수 있습니다.

내부 명령어

Claude Code와 Claude.ai에 기본 내장된 명령어입니다. 별도 설치 없이 /로 호출합니다.

/goal
Claude Code Autonomy

목표만 걸어두고 수단은 Claude가 스스로 정하게 하는 명령. 완료 조건을 충족할 때까지 자율적으로 반복합니다.

  • Claude의 Skill은 SKILL.md와 관련 스크립트·자료를 묶어, Claude에게 특정 업무 절차나 전문 지식을 재사용 가능하게 가르치는 확장 기능
  • Claude가 요청 내용과 Skill의 설명을 보고 자동으로 필요한 Skill을 불러오거나, Claude Code에서는 /skill-name 형태로 직접 실행 가능
  • 즉, 반복해서 입력하던 가이드·체크리스트·업무 절차를 한 번 만들어 두고 필요할 때 재사용하는 개념이며, ChatGPT의 Skill과 기본 철학은 같음
유의 — 오래 실행될수록 비용이 커질 수 있어, 짧고 구체적인 완료 기준 설정이 중요합니다.
/deep-research
Claude Code · Claude.ai Research

심층 리서치 워크플로우. 실행 환경에 따라 정확성 중심(Claude Code)과 폭넓은 탐색(Claude.ai)으로 성격이 나뉩니다.

Claude Code · /deep-research

여러 서브에이전트가 병렬 조사하고 결과를 교차검증·투표하여 신뢰도가 낮은 주장을 걸러내는 정확성 중심 워크플로우.

Claude.ai · Research

웹과 연결된 Google Workspace를 자율적으로 반복 검색·분석하여, 인라인 출처가 포함된 폭넓은 심층 리서치 보고서를 생성.

적합한 상황

빠르고 폭넓은 개인/업무 정보 조사는 Claude.ai Research, 팀 공유용으로 철저한 검증이 필요한 조사는 Claude Code /deep-research가 적합합니다.

/goal
Claude Code Autonomy

목표만 걸어두고 수단은 Claude가 스스로 정하게 하는 명령. 완료 조건을 충족할 때까지 자율적으로 반복합니다.

  • Claude Code의 내장 명령으로, 완료 조건을 설정하면 사용자의 추가 프롬프트 없이 조건을 충족할 때까지 자율 반복합니다.
  • 매 턴마다 별도의 빠른 모델이 대화 기록을 바탕으로 목표 달성 여부를 평가하므로, 테스트 통과·컴파일 성공처럼 결과로 검증 가능한 완료 조건을 명확히 정의하는 것이 핵심.
  • 대규모 코드 수정·마이그레이션·백로그 처리 등 명확한 종료 상태가 있는 장기 작업에 유용합니다.
유의 — 오래 실행될수록 비용이 커질 수 있어, 짧고 구체적인 완료 기준 설정이 중요합니다.
/batch
Claude Code Parallel

코드베이스 전반의 대규모 병렬 변경 명령. 하나의 큰 변경을 여러 작업 단위로 쪼개 여러 에이전트가 동시에 처리합니다.

  • 코드베이스 전체 작업을 분석해 5~30개의 독립 작업 단위로 분해하고 여러 에이전트가 병렬 처리합니다.
  • 실행 전 작업 계획 승인을 받고, 각 작업을 격리된 Git worktree에서 수행한 뒤 완료 결과를 PR로 만들어 안전성·관리성을 높입니다.
  • 프레임워크 마이그레이션·대량 리팩터링·반복 코드 변경처럼 넓은 범위의 작업에 적합하며, 최근 변경 파일을 정리하는 /simplify보다 코드베이스 전반의 대규모 변경에 특화되어 있습니다.
유의 — 토큰 사용량이 많을 수 있습니다.
/doctor
Claude Code Diagnostics

설치·설정 자가진단 명령. 런처·설정·권한·MCP 연결·업데이트·컨텍스트 문제를 한 번에 점검합니다.

  • 최신 버전에서는 단순 진단을 넘어 발견된 문제의 수정까지 지원하며, /doctor·/checkup 또는 세션 시작이 안 될 때 claude doctor로 실행할 수 있습니다.
  • 스킬/플러그인 과다, 비대한 CLAUDE.md, 느린 훅 등 침묵 실패(silent failure)까지 탐지합니다.
  • /status가 현재 상태의 스냅샷이라면, /doctor는 문제를 적극적으로 찾아 고치는 종합검진에 가깝습니다.

3rd Party Skill — 별도 설치 필요

Anthropic 외부에서 만들어 설치해서 쓰는 스킬·플러그인입니다. 대부분 npx skills add 또는 /plugin marketplace add → /plugin install로 설치합니다.

/plan-plus
bkit Planning

기획/개발 아이디어를 인터뷰 형식으로 구체적으로 다듬는 bkit 스킬. 아이디어·개발 요구사항을 실행 가능한 계획으로 만듭니다.

  • /plan 모드는 코딩 전에 계획 수립을 강제하는 읽기 전용 모드입니다.
  • 파일 탐색·검색은 가능하지만 Edit/Write/Bash 등 변경·실행 도구는 차단되어, 먼저 단계별 계획을 검토·승인한 뒤 실제 구현 단계로 넘어갑니다.
  • Plan Mode는 Haiku 기반 Explore 서브에이전트로 코드베이스를 사전 탐색하므로, 메인 컨텍스트를 절약하면서 계획의 정확도를 높이는 데 적합합니다.
Install · bkit 플러그인 (plan-plus 포함)
claude plugin install bkit
superpowers
obra · GitHub Framework

Claude Code를 “규율 있는 엔지니어”로 만드는 스킬 프레임워크. 질문하고 설계하면서 진행하며, 필요에 따라 On/Off하며 쓰는 것이 좋습니다.

  • Jesse Vincent(obra)이 만든 프레임워크로, 코드를 쓰기 전에 브레인스토밍 → 계획 → TDD 구현 → 리뷰로 이어지는 개발 방법론을 강제합니다.
  • 작업 유형을 감지해 관련 스킬을 자동 활성화합니다 — 예: 기능 요청 시 설계 대화, 버그 시 체계적 디버깅.
  • Claude Code·Cursor·Codex 등 여러 에이전트에서 동작하는 플랫폼 불문 구조입니다.
Install
/plugin install superpowers@claude-plugins-official
gstack
Garry Tan Team-in-a-box

내부에 54개의 스킬이 들어 있는 프레임워크(초보자에게는 쉽지 않음). 단일 AI 어시스턴트를 CEO급 제품 리뷰부터 자동화 QA 테스트, 원커맨드 배포까지 아우르는 전문가 팀으로 바꿔줍니다.

  • 대부분의 초기 스타트업이 “사람보다 할 일이 많다”는 벽에 부딪히는데, Garry Tan은 이 제약의 대응으로 GStack을 만들어 솔로 개발자가 한 세션에서 여러 스타트업 기능을 처리하도록 Claude Code를 구조화했습니다.
  • 각 스킬 = 팀 내 역할. 슬래시 명령으로 호출해 필요에 따라 인지 모드(cognitive mode)를 전환합니다.
  • 제품 재구상(CEO 관점) — 당연한 기능을 구현하는 대신 요청 속에 숨은 “10점짜리 제품”을 찾아, 이 제품이 실제로 무엇을 위한 것인지 묻습니다.
  • 아키텍처 설계 — 데이터 흐름·상태 전이·엣지 케이스·실패 모드·테스트 커버리지를 확정하며, 시퀀스·상태·컴포넌트·데이터 흐름 다이어그램으로 숨은 가정을 표면화합니다.
  • 구조적 코드 감사 — CI는 통과하지만 프로덕션에서 터지는 버그(N+1 쿼리, 경쟁 조건, 신뢰 경계 위반, 누락된 인덱스, 깨진 재시도 로직, 스테일 리드)를 찾습니다.
Install · GStack 마켓플레이스 추가 후 설치 (정확한 repo 경로 확인 필요)
/plugin marketplace add <owner>/gstack → /plugin install gstack@<marketplace>
유의 — 스킬 수가 많아 초보자가 다루기는 쉽지 않습니다.
Karpathy skill
multica-ai Principles

LLM 코딩 실수를 줄이는 원칙 스킬. 코딩 전 사고·단순성·최소 변경·목표 주도 실행이라는 네 가지 원칙을 강제합니다.

  • Think Before Coding — 가정을 명시적으로 진술하고, 대안적 해석을 제시하고, 모호할 때는 물어봅니다.
  • Simplicity First — 요청된 것만 해결하는 최소한의 코드. 추측성 기능 없음, 조급한 추상화 없음.
  • Surgical Changes — 요청이 요구하는 것만 편집하고, 기존 스타일을 따르며, 잘 작동하는 코드를 리팩터링하지 않습니다.
  • Goal-Driven Execution — 검증 가능한 성공 기준을 세웁니다.
Install · 패키징된 Claude Code 플러그인 (현재 소스: multica-ai)
/plugin marketplace add … → /plugin install
taste-skill
Leonxlnx · GitHub Design

AI가 만드는 뻔한 디자인(AI-slop)을 제거하는 것이 목적인 스킬. GitHub에서 가져와 내 스킬로 등록하면 개성 있는 페이지 구성이 가능합니다.

  • 브리프를 읽고 디자인 언어를 추론한 뒤, 세 개의 다이얼(VARIANCE · MOTION · DENSITY)을 조절해 결과의 표현 강도를 튜닝합니다.
  • AI가 반복하는 기본값(보라색 그라디언트, 중앙 히어로, 동일한 3개 카드, Inter 폰트 등)을 안티-슬롭 규칙으로 차단합니다.
  • React·Vue·Svelte 등 프레임워크 불문으로 동작하며, 마케팅 페이지·포트폴리오·리디자인에 특히 유효합니다(제품 UI·대시보드에는 부적합).
Install
npx skills add https://github.com/Leonxlnx/taste-skill --skill design-taste-frontend
sonner
GitHub UI / Motion

깃허브에 있는 스킬로, 버튼에 마우스를 올리면 반응하는 것 등 감각적인 인터랙션·모션 디자인을 적용할 수 있게 해줍니다.

  • 원조 Sonner는 React용 토스트(알림) 컴포넌트 라이브러리로, 부드러운 등장·퇴장 애니메이션과 스택 처리로 잘 알려져 있습니다.
  • 스킬로 등록하면 에이전트가 호버 반응·전환·마이크로 인터랙션 같은 세련된 피드백 패턴을 UI에 자연스럽게 넣도록 유도합니다.
  • taste-skill처럼 디자인 감도를 올리는 보조 스킬로, 밋밋한 정적 UI에 생동감을 더하고 싶을 때 조합해 쓰기 좋습니다.

remotion
remotion.dev Video

영상 관련 스킬로, 내부적으로 여러 개(약 12개)의 스킬이 추가로 들어 있습니다. React 코드로 영상을 프로그래밍적으로 제작합니다.

  • Remotion은 React 컴포넌트로 영상을 만드는 오픈소스 프레임워크로, 타임라인 편집 없이 <Sequence>·interpolate()·spring() 등으로 애니메이션을 코드로 정의합니다.
  • 스킬은 생성·마크업·렌더·맵 애니메이션 등 하위 스킬로 나뉘어, 상황에 맞는 세부 지식을 로드합니다.
  • 제품 데모·데이터 시각화·체인지로그·소셜 클립처럼 코드로 반복 생성하는 영상에 적합합니다(“영상 = 빌드 산출물”).
Install · 공식 Agent Skills (프로젝트 안에서 실행)
npx skills add remotion-dev/skills #또는 npx remotion skills add
유의 — MP4 렌더에는 로컬 렌더링 환경(Node/FFmpeg 등) 설정이 필요할 수 있습니다.
Templates 새 항목 추가용 스니펫

카테고리별 카드 추가하기

카드는 두 카테고리가 같은 구조를 씁니다. 차이는 클래스뿐입니다 — 내부 명령어는 class="cmd embed", 외부 스킬은 class="cmd thirdp". 원하는 카테고리의 <div class="cmd-list"> 안에 붙여넣고, 상단 네비/모바일 메뉴에 링크 한 줄만 추가하면 됩니다.

Embedded Skill 카드

#embedded 섹션의 cmd-list 안에 추가하세요.

embedded-card.snippet.html
<article class="cmd embed" id="your-command">
  <div class="cmd-head">
    <div class="cmd-name"><span class="slash">/</span>your-command</div>
    <span class="cmd-src">Claude Code</span>
    <span class="cmd-tag a">Category</span>  <!-- a/b/c -->
  </div>
  <div class="cmd-body">
    <p class="cmd-summary">한 줄 요약.</p>
    <ul class="cmd-notes">
      <li>세부 동작.</li>
    </ul>
    <div class="fit-box"><div class="flabel">적합한 상황</div><p>...</p></div>
    <div class="warn-box"><b>유의 —</b> ...</div>
  </div>
</article>

3rd Party Skill 카드

#thirdparty 섹션의 cmd-list 안에 추가하세요. cmd-src에 제공처(Provider), 필요하면 install-box에 설치 명령을 적어둡니다.

thirdparty-card.snippet.html
<article class="cmd thirdp" id="skill-name">
  <div class="cmd-head">
    <div class="cmd-name">skill-name</div>
    <span class="cmd-src">Provider · GitHub</span>
    <span class="cmd-tag p">Category</span>
  </div>
  <div class="cmd-body">
    <p class="cmd-summary">한 줄 요약.</p>
    <ul class="cmd-notes">
      <li>세부 동작 / 특징.</li>
    </ul>
    <!-- 설치 명령이 있으면 -->
    <div class="install-box"><div class="ilabel">Install</div>
      <code>npx skills add ...</code></div>
  </div>
