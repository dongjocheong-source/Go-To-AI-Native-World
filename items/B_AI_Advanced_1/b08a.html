Claude Skills vs Subagent 완벽 가이드

Skill과 Subagent는 서로 다른 문제를 해결한다. Skill은 모든 컨텍스트에 로드할 수 있는 재사용 가능한 콘텐츠이고, Subagent는 주 대화와 별도로 실행되는 격리된 워커다.

Overview

Skill과 Subagent의 차이

둘 다 "확장" 도구지만 방향이 다르다. Skill은 지식을 컨텍스트 안으로 가져오고, Subagent는 작업을 컨텍스트 밖으로 내보낸다.

Skill

지침 → 주 컨텍스트에 로드

재사용 가능한 지침, 지식 또는 워크플로우. 참조 skill은 세션 전체에서 쓰는 지식(API 스타일 가이드 등)을, 작업 skill은 특정 작업 수행 방법(배포 절차 등)을 제공한다.

Subagent

작업 → 격리된 워커 → 결과만 반환

자신의 컨텍스트 윈도우를 가진 독립된 워커다. 많은 컨텍스트를 소모하는 작업이나 광범위한 검색을 대신 처리하고, 주 대화에는 요약된 결과만 돌려준다.

Deep Dive

Skill재사용 가능한 콘텐츠

참조 skill은 Claude가 세션 전체에서 사용하는 지식을 제공한다(API 스타일 가이드처럼). 작업 skill은 특정 작업을 수행하도록 지시한다(배포 절차처럼).

1
재사용성모든 컨텍스트에 로드할 수 있다 — 한 번 작성하고 여러 대화, 여러 프로젝트에서 사용한다.
2
주 윈도우에 추가스킬 콘텐츠는 주 컨텍스트 윈도우에 그대로 더해진다 — 길어질수록 더 많은 토큰을 소비한다.
3
참조 + 워크플로우정보를 제공하는 참조형과, 절차를 지시하는 워크플로우형 모두를 포괄한다.
사용 사례
  1. Python 최적화 가이드 — Claude와의 모든 대화에서 활용해 일관된 코딩 스타일을 유지
Deep Dive

Subagent격리된 워커

상당한 양의 컨텍스트를 소모하거나 광범위한 검색을 실행할 수 있지만, 주 대화에는 요약만 돌아가면 되는 작업에 유용하다.

1
격리자신의 컨텍스트를 가진 독립 워커다 — 중간 과정을 주 대화에 노출할 필요가 없다.
2
컨텍스트 절약자신의 입력과 충분한 토큰이 있는 별도의 윈도우를 사용해 주 대화의 컨텍스트를 아낀다.
3
병렬 처리에 적합여러 Subagent를 동시에 띄워 독립적인 작업을 병렬로 처리할 수 있다.
사용 사례
  1. 대규모 데이터 분석 — 큰 CSV 파일 처리를 Subagent에 맡기고, 최종 결과만 주 대화로 반환받는다.
Use Cases

실제 시나리오별 선택

시나리오 01 코드 스타일 가이드 공유
Skill · 참조형

상황: 팀 전체가 동일한 Python 코딩 스타일을 지켜야 한다.

모든 개발자의 대화에서 재사용일관된 기준 유지참조용으로만 사용
# Python 코딩 스타일 가이드 ## 네이밍 컨벤션 - 함수: snake_case / 클래스: PascalCase / 상수: UPPER_SNAKE_CASE ## 들여쓰기 - 4 스페이스 사용
시나리오 02 대규모 데이터 처리 워크플로우
Subagent · 격리 워커

상황: 1GB 데이터 파일을 처리하는 복잡한 분석이 필요하다.

메인 컨텍스트 보존 필수많은 처리 능력 필요최종 결과만 반환하면 됨
subagent = { "name": "데이터 분석 워커", "task": "1GB CSV 파일 분석", "skills": ["데이터 처리 가이드"] # 필요한 스킬 참고 }
시나리오 03 배포 프로세스 자동화
Skill · 작업형(/deploy)

상황: 여러 프로젝트에서 동일한 배포 프로세스를 실행해야 한다.

여러 프로젝트에서 재사용호출 가능한 워크플로우표준화된 절차 유지
# 배포 스킬 1) 테스트 실행 → 2) 빌드 생성 → 3) 배포 수행 → 4) 검증 실행 방법: Claude에게 "/deploy" 입력
시나리오 04 다중 언어 번역 작업
Subagent · 병렬 워커

상황: 100개 문서를 10개 언어로 동시에 번역해야 한다.

병렬 처리로 속도 향상언어별 독립적 처리메인 대화 토큰 절약
subagents = { "korean_translator": {...}, "english_translator": {...}, "spanish_translator": {...}, # ... 나머지 7개 언어, 동시 실행 }
Decision Guide

의사결정 트리

Q. 여러 대화에서 재사용해야 하는가?
YESSkill 사용 — 참조 자료라면 참조형, 호출 가능한 워크플로우라면 작업형(/deploy)
NO단일 대화 또는 프로젝트 내라면 다음 질문으로 ↓
Q. 컨텍스트 격리가 필요한가? (많은 컨텍스트, 별도 토큰 사용)
YESSubagent 사용 — 스킬과 겹친다면 Subagent가 skills 필드로 참고, 아니면 독립적 Subagent
NO주 대화와 함께 진행 — 직접 구현 또는 Skill

Summary

한 문장으로 정리하는 Skill vs Subagent

지식을 컨텍스트 안으로 들여오고 싶다면 Skill, 작업을 컨텍스트 밖으로 내보내고 싶다면 Subagent.

01Skill은 재사용 가능한 지침·지식·워크플로우를 주 컨텍스트에 공유한다.
02Subagent는 컨텍스트를 격리해 대규모·병렬 작업을 처리하고 결과만 반환한다.
03Subagent 안에서도 Skill을 skills 필드로 참고할 수 있다 — 둘은 함께 쓰일 수 있다.
기억할 것 한 줄 — 여러 대화에서 재사용하고 싶다면 Skill, 이번 대화의 컨텍스트를 지키고 싶다면 Subagent.
