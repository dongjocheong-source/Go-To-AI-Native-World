"넌 10년 차 마케터야, 마케팅 플랜 짜줘"라고 묻는 것만으로는 부족합니다. AI는 우리 회사의 현재 예산도, 과거 실패 사례도 모릅니다. LLM에게 전달되는 모든 정보를 체계적으로 설계·선별·압축하는 기술, 컨텍스트 엔지니어링의 정의부터 4대 전략, 실전 구축까지 정리합니다.

Write·Select·Compress·Isolate Python 실전 구축 프롬프트 vs 컨텍스트
Overview

컨텍스트 엔지니어링이란?

대규모 언어 모델(LLM)이 최적의 답변과 행동을 도출할 수 있도록, 모델에게 전달되는 모든 정보(Context)를 체계적으로 설계, 선별, 압축하여 제공하는 시스템 공학입니다.

새로 입사한 신입사원(AI)에게 다짜고짜 "기획서 써와(프롬프트)"라고 지시하는 게 아니라, "우리 회사의 과거 기획서 양식, 이번 프로젝트 예산, 참고할 만한 경쟁사 데이터(컨텍스트)"를 보기 좋게 정리해서 파일철로 건네주는 작업 전체를 설계하는 것입니다.

컨텍스트 윈도우(Context Window)의 이해

LLM이 한 번에 기억하고 처리할 수 있는 정보의 양을 '컨텍스트 윈도우'라고 부릅니다.

GPT-4o — 약 128K 토큰 Claude 3.5 — 약 200K 토큰

컨텍스트 엔지니어링은 이 제한된 메모리 공간을 어떤 정보로, 어떤 순서로 채울 것인가를 결정하는 예술이자 과학입니다.

Core Components

핵심 구성요소

LLM에게 전달되는 완벽한 '컨텍스트 패키지'는 다음 요소들을 동적으로 조립하여 만들어집니다.

1
System Instructions (시스템 프롬프트)AI의 페르소나, 지켜야 할 절대 규칙, 출력 포맷 (예: "넌 사내 HR 봇이며, 반드시 JSON으로 답해라.")
2
Short-term Memory (단기 기억)현재 진행 중인 대화의 히스토리. 길어지면 핵심만 요약(Compress)해야 합니다.
3
Long-term Memory (장기 기억)사용자의 이름, 과거 선호도, 이전 프로젝트 기록 등 세션이 끝나도 유지되어야 할 정보.
4
Knowledge Retrieval (RAG)사내 문서, 매뉴얼, DB에서 현재 질문과 관련된 정보만 검색(Select)해 온 데이터.
5
Tool Results (도구 실행 결과)AI가 외부 API(웹 검색, 계산기 등)를 호출하고 받아온 결과값.
6
Current User Input (현재 사용자 질문)사용자가 방금 입력한 즉각적인 요청.
LangChain 제안

4대 핵심 전략 — Write · Select · Compress · Isolate

성공적인 시스템을 만들기 위해 명심해야 할 4가지 전략입니다.

✏️ Write (기록하기)

AI는 대화가 길어지면 앞의 내용을 까먹습니다. 사용자가 말한 중요한 제약조건(예: "나는 매운 음식은 못 먹어")을 외부 스크래치패드나 메모리에 명시적으로 기록하도록 설계해야 합니다.

🔍 Select (선별하기)

사내 문서 1만 장을 다 던져주면 AI는 정보의 홍수 속에서 핵심을 놓칩니다(Lost in the middle). 현재 질문과 가장 관련성 높은 3~5개의 정보만 검색(Vector Search)하여 제공해야 합니다.

🗜️ Compress (압축하기)

이전 대화 기록이 너무 길어지면 API 비용(토큰)이 폭발하고 추론 능력이 떨어집니다. 10턴이 넘어간 대화는 LLM으로 "지금까지의 요약본"으로 압축해야 합니다.

🗂️ Isolate (격리하기)

'여행 일정' 메모리와 '연말 정산' 메모리가 섞이면 AI가 엉뚱한 대답을 합니다. 주제별로 정보를 분리하여 저장하고 호출해야 합니다.

Trade-offs

특징 및 장단점

✅ 장점

·
환각의 극적인 감소모델이 지어내는 대신, 주어진 탄탄한 컨텍스트(사내 문서 등) 안에서만 대답하므로 신뢰성이 압도적으로 높아집니다.
·
복잡한 비즈니스 로직 처리 가능단순 문답을 넘어 수십 단계의 멀티 에이전트 시스템(Agentic AI)을 안정적으로 구동할 수 있습니다.
·
토큰 최적화 및 비용 절감필요한 정보만 압축해서 전달하므로 불필요한 토큰 낭비를 막아 API 호출 비용을 크게 줄여줍니다.

❌ 단점 및 도전 과제

·
Lost in the Middle컨텍스트가 너무 길면 LLM은 처음과 끝은 잘 기억하지만 중간에 끼워진 정보는 무시하는 경향이 있습니다. 중요한 지시사항은 맨 앞이나 맨 뒤에 배치해야 합니다.
·
구현의 복잡성단순한 프롬프트 호출이 아니라, 벡터 DB 연동·메모리 요약 파이프라인 구축 등 고난도의 소프트웨어 엔지니어링 역량이 필요합니다.
[실습]

Python으로 구현하는 Context Engineering 파이프라인

단순히 프롬프트를 쏘는 것을 넘어, 사용자의 프로필, 검색된 사내 규정, 과거 대화 이력을 하나의 완벽한 컨텍스트로 조립(Assembly)하여 LLM에 전달하는 코드를 구현해봅니다.

context_engine.py
import json, os
from openai import OpenAI
from datetime import datetime

# 1. API 클라이언트 초기화 (환경변수 세팅 필요)
client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

# 2. 컨텍스트를 동적으로 조립하는 핵심 엔진 함수
def build_optimized_context(user_query: str, user_profile: dict,
                             retrieved_docs: list, chat_history: list) -> list:
    # 다양한 소스의 정보를 수집·압축해 LLM이 이해하기 가장 좋은 형태(Messages)로 조립

    # [1] 시스템 프롬프트 (System Context) — AI의 역할과 절대 규칙 부여
    system_instruction = f"당신은 사내 HR(인사) 전문 AI 어시스턴트입니다.
현재 날짜: {datetime.now().strftime('%Y-%m-%d')}

[사용자 정보]
- 이름: {user_profile['name']}
- 직급: {user_profile['rank']}
- 부서: {user_profile['department']}

[응답 규칙]
1. 반드시 아래 제공된 <사내규정> 정보만을 기반으로 답변하세요.
2. 모르는 내용은 "규정에서 찾을 수 없습니다"라고 답변하세요.
3. 사용자 직급({user_profile['rank']})에 맞는 정중한 어투를 사용하세요."

    # [2] 검색된 문서 주입 (Knowledge Context / RAG)
    if retrieved_docs:
        system_instruction += "\n\n<사내규정>\n"
        for i, doc in enumerate(retrieved_docs, 1):
            system_instruction += f"문서{i}: {doc}\n"
        system_instruction += "</사내규정>"

    # 메시지 리스트 초기화 (시스템 프롬프트 삽입)
    messages = [{"role": "system", "content": system_instruction}]

    # [3] 과거 대화 이력 주입 (Memory Context)
    # 토큰 절약을 위해 최근 4개의 대화만 유지 (Compress & Select 전략)
    recent_history = chat_history[-4:] if len(chat_history) > 4 else chat_history
    messages.extend(recent_history)

    # [4] 현재 사용자 질문 주입 (User Input)
    # Lost in the middle 현상을 방지하기 위해 가장 중요한 질문을 맨 마지막에 배치
    messages.append({"role": "user", "content": user_query})

    return messages

# 3. 테스트 실행 환경 셋팅
if __name__ == "__main__":
    # 가상의 외부 데이터 소스들 (실제로는 DB나 Vector Store에서 가져옴)
    mock_user_profile = {"name": "김개발", "rank": "선임", "department": "AI연구소"}
    mock_retrieved_docs = [
        "경조사 휴가 규정: 본인 결혼 시 5일의 특별 휴가가 부여됩니다.",
        "복지 포인트: 선임급 이상은 연 100만 포인트가 1월 1일에 지급됩니다."
    ]
    mock_chat_history = [
        {"role": "user", "content": "안녕, 오늘 컨디션 어때?"},
        {"role": "assistant", "content": "안녕하세요 김개발 선임님! 무엇을 도와드릴까요?"}
    ]

    # 사용자의 새로운 질문
    current_query = "나 다음 달에 결혼하는데 휴가 며칠 쓸 수 있어? 복지포인트는 얼마나 나와?"

    print("⚙️ [시스템 로그] 컨텍스트를 동적으로 조립 중입니다...")

    # 컨텍스트 엔지니어링 수행
    final_messages = build_optimized_context(
        user_query=current_query, user_profile=mock_user_profile,
        retrieved_docs=mock_retrieved_docs, chat_history=mock_chat_history
    )

    print("🚀 [시스템 로그] 완성된 컨텍스트를 LLM에 전달합니다...")

    # LLM 호출
    response = client.chat.completions.create(
        model="gpt-4o-mini", messages=final_messages,
        temperature=0.1  # 사실 기반 답변을 위해 창의성 낮춤
    )

    print("🤖 [AI 어시스턴트 답변]")
    print(response.choices[0].message.content)
▶ 🤖 [AI 어시스턴트 답변]
김개발 선임님, 결혼을 진심으로 축하드립니다!
사내 규정에 따르면 본인 결혼 시 5일의 특별 휴가를 사용하실 수 있습니다.
또한, 선임급이시므로 연 100만 복지 포인트가 1월 1일에 지급됩니다. 추가로 궁금한 점이 있으시면 언제든 말씀해 주세요.
모델은 단순히 질문만 받은 게 아니라, '김개발이 선임이라는 프로필 정보'와 '사내 규정'이라는 완벽하게 조립된 컨텍스트를 전달받았기에 정확하고 맥락에 맞는 답변을 생성할 수 있었습니다.
At a Glance

프롬프트 엔지니어링 vs 컨텍스트 엔지니어링

이 두 개념은 경쟁 관계가 아니라 계층적 관계입니다.

비교 항목프롬프트 엔지니어링컨텍스트 엔지니어링
핵심 목적"무엇을, 어떻게 말하게 할 것인가?""어떤 배경지식을, 언제 줄 것인가?"
작업 범위단일 텍스트 문자열 (질문, 지시사항)시스템 전체의 정보 아키텍처 (DB, 메모리, 도구)
성격작문, 텍스트 다듬기에 가까움소프트웨어 아키텍처 및 파이프라인 설계
적용 시나리오1회성 번역, 요약, 단순 아이디에이션사내 RAG 챗봇, 자율형 AI 에이전트, 코딩 어시스턴트
비유아나운서의 대본을 잘 써주는 것앵커에게 필요한 모든 뉴스 자료와 팩트를 세팅해주는 것
Conclusion

마치며 — 질문하는 자에서, 시스템을 설계하는 자로

"더 나은 질문은 더 나은 답변을 낳지만, 더 나은 시스템은 더 나은 솔루션을 만듭니다."

프롬프트 엔지니어링의 시대에는 AI의 기분을 맞추고 교묘하게 말을 돌려 원하는 답을 얻어내는 데 집중했습니다. 하지만 본격적인 기업용 AI 도입과 AI 에이전트의 시대가 열린 지금, AI가 참고할 수 있는 지식의 풀(Pool)을 어떻게 깔끔하게 정리해서 적재적소에 먹여줄 것인가가 성공의 핵심이 되었습니다.

Cursor AI나 Claude Code 같은 최첨단 AI 코딩 툴들이 압도적인 성능을 내는 이유도, AI 모델이 특별히 뛰어나서가 아닙니다. 사용자가 코딩하는 현재 파일, 과거의 수정 내역, 에러 로그, 전체 프로젝트 폴더 구조를 백그라운드에서 완벽하게 조립하여 컨텍스트 윈도우에 찔러 넣어주는 '극강의 컨텍스트 엔지니어링 기술'이 탑재되어 있기 때문입니다.

기억할 것 한 줄 — 앞으로 AI 서비스 기획자나 개발자라면 프롬프트를 다듬는 것을 넘어, 데이터 파이프라인과 메모리 구조를 설계하는 컨텍스트 엔지니어(Context Engineer)로 시야를 넓혀야 할 때입니다 🚀
