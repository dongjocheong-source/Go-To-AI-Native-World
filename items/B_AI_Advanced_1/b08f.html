Hook vs Skill — 자동 실행과 지침 해석의 차이

Hook은 라이프사이클 이벤트에서 무조건 실행되는 반사 신경이고, Skill은 Claude가 상황을 판단해 불러오는 지침이다. "매번 똑같이 실행되어야 하는가, Claude가 판단해야 하는가"가 둘을 가르는 기준이다.

Overview

핵심 정의

Hook은 라이프사이클 이벤트에서 실행된다. Skill은 Claude의 컨텍스트에 로드된다. 이 한 문장이 둘의 모든 차이를 설명한다.

Hook

이벤트 → 자동 실행

셸 명령, HTTP 요청, LLM 프롬프트 또는 subagent 같은 특정 이벤트(PostToolUse, SessionStart 등)에 반응해 트리거된다. Claude의 판단이 개입하지 않는다.

Skill

필요 → Claude가 판단 → 로드

Claude가 알고 따르는 지침이다. /<name>을 직접 입력하거나, Claude가 대화 중 이 지침이 필요하다고 판단할 때 불러온다.

핵심 차이 — Hook은 "트리거가 보장"된다. 이벤트가 발생하면 무조건 실행된다. Skill은 Claude가 지침을 "해석"한다. 같은 스킬이라도 상황에 따라 적용 방식이 달라질 수 있다.

Deep Dive

Hook라이프사이클 이벤트에서 실행

셸 명령, HTTP 요청, LLM 프롬프트 또는 subagent를 특정 이벤트에 자동으로 연결한다.

1
자동 트리거라이프사이클 이벤트(PostToolUse, SessionStart, PreToolUse 등)가 발생하면 무조건 실행된다.
2
보장된 실행Claude의 판단을 거치지 않는다 — 조건이 맞으면 실행, 그걸로 끝이다.
3
매우 낮은 컨텍스트 비용hook이 결과를 반환하지 않는 한 컨텍스트를 거의 소모하지 않는다.
주요 트리거 포인트
  1. PostToolUse — 도구 사용 직후 자동 실행. 예: rm -rf 실행 → 확인 hook 실행
  2. SessionStart — 세션 시작 시 자동 실행. 예: 환경 설정, 초기화
  3. PreToolUse — 도구 실행 전에 자동 실행. 예: 위험한 명령 사전 확인
자동으로 실행되어야 함 Claude의 결정 불필요 매번 동일하게 실행되어야 함 파일 시스템 작업(rm -rf, chmod) 세션 초기화
Deep Dive

SkillClaude가 알고 따르는 지침

참조 자료로 쓰이거나(예: API 스타일 가이드), 작업을 지시하는 워크플로우로 쓰인다(예: 배포 절차).

1
명시적 로드사용자가 /<name>으로 직접 부르거나, Claude가 작업 맥락상 필요하다고 판단해 불러온다.
2
Claude가 판단 + 실행지침을 그대로 따르는 게 아니라 해석한다 — 같은 스킬도 상황에 따라 다르게 적용될 수 있다.
3
필요할 때만 로드설명(description)은 모든 세션에 항상 실려 있지만, 전체 콘텐츠는 실제로 쓰일 때만 로드된다.
트리거 방법
  1. 직접 호출 — 사용자가 "/release"라고 입력 → Claude가 release 스킬을 로드하고 실행
  2. 상황 판단 — 사용자가 "코드 검토해줘" → Claude가 code-review 스킬이 도움될 것으로 판단해 스스로 로드
  3. 파일 경로 인식 — 특정 디렉토리의 파일을 다룰 때 그에 맞는 규칙 스킬을 로드
Claude가 지침을 해석해야 함 상황에 따라 결과가 달라짐 콘텐츠 자체가 지침 또는 정보 코드 검토 가이드 API 스타일 가이드 배포 체크리스트
Use Cases

실제 시나리오별 선택

시나리오 01 중요 파일 삭제 방지
Hook · PreToolUse

상황: 실수로 rm -rf가 실행되는 것을 막아야 한다.

자동 확인 필요Claude의 판단 불필요매번 실행되어야 함위험한 명령만 감지
사용자: "rm -rf /home/user/documents" Hook 작동: 1) 위험한 명령 감지 2) 자동 확인 — "정말 삭제하시겠습니까?" 3) 사용자 확인 필요 → Hook이 없으면 파일이 그냥 삭제된다.
시나리오 02 배포 체크리스트
Skill · /release

상황: 배포할 때마다 확인 항목을 검토해야 한다.

체크리스트 해석 필요항목별 판단하며 진행상황에 따라 다름사용자 요청으로 트리거
사용자: "/release" Skill 작동: 1) release 스킬 로드 2) Claude가 각 항목을 검토 3) 항목별 상태 확인 4) 배포 진행 → Claude가 지침을 이해하고 판단하며 진행한다.
시나리오 03 파일 시스템 권한 관리
Hook · SessionStart

상황: 세션이 시작될 때마다 중요 파일 권한을 자동으로 맞춰야 한다.

세션마다 자동 실행Claude의 판단 불필요항상 같은 방식초기화 작업
SessionStart → 자동 실행: 1) .env 권한 644로 설정 2) private key 권한 600으로 설정 3) 프로젝트 폴더 권한 설정 → 매 세션마다 자동으로 권한이 초기화된다.
시나리오 04 코드 검토 가이드
Skill · /code-review

상황: 코드를 검토할 때마다 체크리스트를 유연하게 적용해야 한다.

가이드 해석 필요코드 특성마다 강조점이 다름사용자 또는 Claude의 판단유연한 적용 필요
사용자: "이 코드 검토해줘" Skill 작동: 1) code-review 스킬 로드 2) Claude가 가이드라인 이해 3) 코드 특성에 맞게 검토 4) 우선순위별 피드백 → Claude가 가이드라인을 해석하며 유연하게 검토한다.
Decision Guide

선택 가이드

자동화 또는 지침을 추가하고 싶을 때, 아래 순서로 물어본다.

Q. 자동으로 매번 실행되어야 하는가?
YES매번 같은 방식으로 → Hook 사용 (PostToolUse 또는 SessionStart)
예: 파일 삭제 확인, 환경 초기화
NO상황에 따라 달라진다면 다음 질문으로 ↓
Q. Claude가 판단하며 진행해야 하는가?
YESSkill 사용 — 예: 코드 검토, 배포 체크리스트
NOHook으로 충분하다
Hook 체크리스트
  • 자동으로 매번 실행되어야 하는가?
  • Claude의 판단이 불필요한가?
  • 위험한 작업 방지가 필요한가?
  • 초기화 · 설정 작업인가?
모두 YES → Hook 사용
Skill 체크리스트
  • Claude가 지침을 해석해야 하는가?
  • 상황에 따라 달라지는가?
  • 사용자 요청으로 트리거되는가?
  • 유연한 적용이 필요한가?
하나 이상 YES → Skill 사용
Implementation

Hook + Skill 조합 전략

둘은 경쟁 관계가 아니라 보완 관계다. Hook이 자동으로 위험을 방지하는 동안, Skill이 판단이 필요한 절차를 안내한다.

Hook 완전한 프로젝트 보호 전략

hooks.md
# PreToolUse hook: 위험한 명령 확인
if command is "rm -rf" or similar:
    stop_and_confirm_with_user()

# SessionStart hook: 환경 초기화
chmod 644 .env       # 읽기만 가능
chmod 600 id_rsa     # 소유자만 읽음
chmod 755 bin/       # 실행 가능

Skill /security-checklist

security-checklist.md
# 보안 검토 항목
- [ ] 환경 변수 확인
- [ ] 권한 설정 확인
- [ ] API 키 안전 여부
- [ ] 로깅 설정 확인
작동 방식 — Hook이 SessionStart로 권한을 자동 초기화하고, Claude가 위험한 명령을 만나면 PreToolUse hook이 자동으로 확인을 받는다. 그 위에서 사용자가 "/security-checklist"를 요청하면 Skill이 수동으로 보안 검토를 진행한다.
Best Practices

모범 사례

Hook 베스트 프랙티스

01
명확한 이벤트 선택PostToolUse는 도구 실행 후, SessionStart는 세션 시작 시 — 목적에 맞는 이벤트를 고른다.
02
빠른 실행Hook은 빨라야 한다. 무거운 작업은 넣지 않는다.
03
오류 처리Hook 실패 시의 대처와 사용자 안내를 준비해둔다.

Skill 베스트 프랙티스

01
명확한 이름과 설명/deploy는 배포, /code-review는 검토 — 이름만 보고 용도를 알 수 있어야 한다.
02
유연한 구조여러 상황에 적용 가능하도록, Claude가 판단할 여지를 설계에 남겨둔다.
03
정기적 업데이트프로세스가 바뀌면 스킬도 함께 갱신하고 버전을 관리한다.
Summary

한 문장으로 정리하는 Hook vs Skill

"매번 똑같이, 무조건" 실행되어야 한다면 Hook. "그때그때 판단"이 필요하다면 Skill.

01Hook은 라이프사이클 이벤트에 반응해 자동으로, 무조건 실행된다 — 트리거가 보장된다.
02Skill은 Claude의 컨텍스트에 로드되는 지침이다 — Claude가 해석하고 판단하며 적용한다.
03둘은 대체재가 아니라 조합된다 — Hook이 안전망을 자동으로 깔고, Skill이 판단이 필요한 절차를 안내한다.
기억할 것 한 줄 — Claude가 생각할 필요가 없다면 Hook, Claude가 생각해야 한다면 Skill.
