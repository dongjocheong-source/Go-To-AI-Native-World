# Claude 아티팩트(Artifacts) 완전 매뉴얼

> 최종 업데이트: 2026년 8월
> 대상: Claude.ai / Claude 데스크톱·모바일 앱 사용자
> 목적: 아티팩트의 개념, 지원 콘텐츠, 생성·편집·공유 방법, AI 내장 앱 구축, 한계와 대응법을 하나의 문서로 정리

---

## 1. 아티팩트란 무엇인가

아티팩트(Artifacts)는 Claude가 생성한 **독립적이고 실질적인 콘텐츠**를 대화창과 분리된 전용 패널에 표시해 주는 기능이다. 긴 코드나 문서를 채팅 말풍선 안에서 읽는 불편함을 없애고, 결과물에 고유한 작업 공간을 부여해 실시간 미리보기와 반복 수정을 가능하게 한다.

핵심 개념을 정리하면 다음과 같다.

- **분리된 작업 공간**: 화면이 좌우로 나뉘어, 왼쪽 채팅창에서 지시하고 오른쪽 패널에서 결과를 실시간 확인한다.
- **자립형(self-contained) 콘텐츠**: 대체로 15줄 이상이면서, 이후 수정·재사용될 가능성이 높은 콘텐츠가 아티팩트로 만들어진다.
- **반복 수정**: "조금 더 크게", "색을 바꿔줘" 같은 후속 지시로 전체를 다시 생성하지 않고 부분만 갱신할 수 있다.
- **파일이자 앱**: 이름을 갖고 대화가 끝나도 사이드바에 보존되므로, 채팅 기록을 스크롤하지 않고도 다시 찾을 수 있다.

아티팩트는 2024년 6월 Claude 3.5 Sonnet과 함께 처음 등장했으며, 단순 미리보기 창에서 시작해 앱을 만들고 호스팅하고 공유하는 플랫폼으로 확장되었다.

## 2. 활성화 및 사전 요구사항

### 2.1 필수 설정

현재 아티팩트는 **Code execution and file creation(코드 실행 및 파일 생성)** 기능이 켜져 있어야 동작한다. 해당 기능 없이는 아티팩트가 지원되지 않는다.

- 개인 플랜(Free, Pro, Max): **Settings > Capabilities**에서 활성화
- 조직 플랜(Team, Enterprise): **Organization settings > Capabilities**에서 활성화

### 2.2 플랜별 지원 범위

| 기능 | Free | Pro | Max | Team | Enterprise |
|------|------|-----|-----|------|------------|
| 사이드바 아티팩트 접근 | O | O | O | O | O |
| Claude 내장(AI-powered) 아티팩트 | O | O | O | O | O |
| Claude Code 내 아티팩트 | X | X | X | O | O |
| 영구 저장소(Persistent storage) | 제한 | O | O | O | O |
| Live Artifacts(실시간 데이터 연동) | X | 유료 | 유료 | 유료 | 유료 |

기본 코드·문서·웹 아티팩트는 무료 플랜에서도 사용 가능하며, 고복잡도 유형과 실시간 데이터 연결은 유료 플랜을 요구한다.

## 3. 지원하는 콘텐츠 유형

아티팩트는 다음 유형을 실시간 미리보기와 함께 생성한다.

1. **코드 스니펫 / 스크립트** — 30개 이상의 프로그래밍 언어를 구문 강조와 함께 표시
2. **Markdown 문서** — 서식이 적용된 장문의 문서, 리포트, 가이드
3. **HTML 페이지** — CSS·JavaScript를 포함한 완전한 단일 페이지(랜딩 페이지, 포트폴리오, 대시보드 등). 독립형 HTML 파일로 다운로드 가능
4. **React 컴포넌트** — 상태 관리(state)를 포함한 인터랙티브 UI
5. **SVG 벡터 그래픽** — 아이콘, 도표, 일러스트. `.svg`로 복사 가능
6. **Mermaid 다이어그램** — 플로우차트, 시퀀스, 상태도 등 텍스트 기반 다이어그램
7. **다운로드 가능한 파일** — `.docx`, `.pptx`, `.xlsx`, `.pdf`
8. **PDF 렌더링** — PDF 문서의 표시

### 아티팩트가 만들어지는 조건

일반적으로 다음을 만족할 때 아티팩트로 생성된다.

- 분량이 상당하다(대략 15줄 이상)
- 대화창 밖에서 사용하거나 저장·공유할 콘텐츠다
- 이후 수정·확장·재사용될 가능성이 높다

반대로 짧은 코드 조각, 간단한 목록, 대화형 설명은 채팅 안에 그대로 표시된다.

## 4. 아티팩트 생성하기

### 4.1 기본 흐름

1. 채팅창에 만들고 싶은 것을 설명한다(예: "예산 계산기 만들어줘").
2. Claude가 코드를 작성하고, 오른쪽에 전용 패널이 열린다.
3. 패널에서 결과를 즉시 확인한다.
4. 후속 메시지로 수정을 요청하면 미리보기가 갱신된다.

### 4.2 좋은 프롬프트 작성 원칙

강한 프롬프트는 다음을 포함한다.

- **아티팩트 유형을 명시**한다("HTML 단일 페이지로", "React 컴포넌트로", "Mermaid 플로우차트로")
- **사용자 상호작용을 서술**한다(무엇을 클릭·입력·필터링할 수 있는지)
- **시각적 기준점을 제시**한다(참고할 스타일, 다크 테마, 색상 팔레트 등)
- **엣지 케이스를 다룬다**(빈 입력, 오류 상태 등)

### 4.3 미리보기 / 코드 전환

아티팩트 창 상단의 토글로 두 가지 모드를 오간다.

- **Preview**: 실제 렌더링 결과(웹페이지, 그래픽, SVG 등)
- **Code**: 생성된 소스 코드

## 5. 편집과 버전 관리

- **반복 수정**: 채팅으로 "여기 여백을 늘려줘", "차트를 막대에서 선으로 바꿔줘"처럼 지시하면 해당 부분만 갱신된다.
- **버전 이력**: 아티팩트는 수정 이력을 유지하지만, 세밀한(shallow) 수준이라 아주 정교한 되돌리기는 제한적이다. 큰 방향 전환이 필요하면 새 대화에서 다시 시작하는 편이 안정적일 때가 있다.
- **사이드바 관리**: 인터페이스의 사이드바에서 생성한 아티팩트를 모아 보고, 새로 만들거나 기존 것을 리믹스(remix)할 수 있다. 아티팩트는 채팅 메시지보다는 파일·앱처럼 이름을 갖고 보존된다.

---

## 6. 공유와 게시(Publish)

1. 아티팩트 패널 하단의 **Publish(게시)** 버튼을 누른다.
2. 생성된 링크를 공유한다.
3. **수신자는 Claude 계정이 없어도 게시된 아티팩트를 볼 수 있다.**
4. 계정이 있는 사용자는 **리믹스**로 자신만의 편집 가능한 사본을 만들 수 있다.

> 참고: 게시를 해제(unpublish)하면 해당 아티팩트의 영구 저장소 데이터가 영구 삭제되며, 같은 아티팩트를 다시 게시할 수 없는 경우가 있으므로 주의한다.

## 7. AI 내장 아티팩트 (AI-powered Apps)

아티팩트에 Claude의 지능을 직접 내장해 **AI 앱**으로 만들 수 있다. 가장 강력한 기능이다.

### 7.1 동작 원리

- 사용자가 Claude에게 원하는 앱을 설명하면 Claude가 코드를 작성한다.
- 앱은 Anthropic 인프라 위에서 실행된다.
- 앱을 쓰는 사람은 **자신의 Claude 계정으로 인증**하고, 각자의 인스턴스로 앱을 사용한다.
- **API 키가 필요 없고, 제작자에게 비용이 청구되지 않는다.** 사용량은 각 사용자 본인의 구독 한도에서 차감된다.
- 따라서 10명이 쓰든 10,000명이 쓰든 공유는 무료다.

### 7.2 만드는 방법

가장 간단하게는 **"Claude를 사용해서 ~하게 해줘"**라고 요청하면 된다. 텍스트 기반 완성(completion)을 앱 안에서 호출하도록 Claude가 코드를 구성한다.

### 7.3 API 호출 개요

아티팩트 내부에서 표준 Anthropic 메시지 엔드포인트를 호출할 수 있다. API 키는 플랫폼이 처리하므로 직접 넣지 않는다.

```javascript
const response = await fetch("https://api.anthropic.com/v1/messages", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    model: "claude-sonnet-4-6",
    max_tokens: 1000,
    messages: [
      { role: "user", content: "여기에 프롬프트" }
    ],
  })
});
const data = await response.json();
// data.content 는 text / tool_use 등 블록의 배열
```

- 응답의 `data.content`는 여러 블록의 배열이므로 **위치가 아니라 블록의 `type`으로 필터링**해 처리한다.
- 구조화된 데이터가 필요하면 시스템 프롬프트에서 "JSON만 출력(백틱·서두 없이)"을 명확히 지시하고, 응답을 안전하게 파싱한다.
- **웹 검색 도구**와 **MCP 서버**를 조합해 외부 서비스와 연동되는 앱도 만들 수 있다.

### 7.4 만들 수 있는 앱 예시

- 학습·교육 도구: 인터랙티브 튜터, 어학 학습 대화 앱
- 콘텐츠 생성 도구: 브레인스토밍 보조, 사내 메시지를 외부 게시물로 다듬는 도구, 원페이지 PRD 작성기
- 분석·의사결정 도구: 데이터 분석기, 코드 리뷰어
- 게임·문제 해결 도구: 플래시카드 앱(사용자가 주제를 직접 고르는 방식 등)

## 8. 영구 저장소 (Persistent Storage)

일부 아티팩트는 세션 간 데이터를 유지할 수 있어, 저널·트래커·리더보드 같은 앱을 만들 수 있다.

**주의사항(개발 시 흔한 함정):**

- 개발(미리보기) 중에는 저장 호출이 조용히 무시(no-op)될 수 있고, **게시(publish) 후에만 실제로 동작**하는 경우가 있다.
- 게시 해제 시 저장 데이터가 영구 삭제될 수 있다.
- 용량 한도가 있으므로(플랜에 따라 상이) 관련 데이터를 하나의 키에 묶는 등 설계에 유의한다.

## 9. Live Artifacts (2026)

2026년 4월 도입된 Live Artifacts는 아티팩트를 **상태를 가지고 연결된(stateful & connected)** 도구로 확장한다.

- MCP 데이터 소스에 연결되어, 열 때마다 **최신 데이터를 자동으로 다시 불러온다.**
- KPI 모니터링, 파이프라인 추적, 콘텐츠 캘린더처럼 수동 갱신 없이 최신 상태를 유지해야 하는 대시보드·트래커에 적합하다.
- 정적 스냅샷이 아니라, 반복적으로 되돌아와 쓰는 살아 있는 도구처럼 동작한다.
- 유료 플랜(Pro, Max, Team, Enterprise)에서 제공된다.

## 10. 한계와 대응 방법

아티팩트는 프로토타입을 빠르게 만드는 데 강하지만, 프로덕션급에는 다음 한계가 있다.

| 한계 | 설명 | 대응 |
|------|------|------|
| 백엔드·DB 없음 | 표준 아티팩트에는 서버·데이터베이스가 없다 | 실제 백엔드·인증·DB는 별도 개발 필요 |
| 단일 파일 제약 | 하나의 파일 구조가 기본 | 복잡한 다중 파일 앱은 외부 개발 환경으로 이전 |
| 외부 API 접근 제한 | 표준 아티팩트는 임의 외부 API 접근이 제한적 | AI 앱은 Anthropic API·MCP를 통해 우회 |
| 대용량 데이터 취약 | 큰 데이터셋·과도한 필터에서 오작동·환각 경향 | 데이터를 줄이고 새 대화에서 시작 |
| 모바일 제약 | 복잡한 React 상호작용은 데스크톱에 유리 | 복잡한 앱은 데스크톱에서 작업 |
| 브라우저 저장 API 미지원 | localStorage/sessionStorage 등은 아티팩트 내에서 실패 | 메모리 내 상태(React state 등) 사용 |
| 이미지 내보내기 버튼 부재 | SVG는 `.svg`로 복사되나 나머지는 스크린샷 필요 | 캡처 도구 활용 |

> 요약: 아티팩트는 작동하는 앱까지 약 70%를 데려다준다. 나머지 30%(실 백엔드, 인증, DB, 인프라)는 전문 개발이 필요한 경우가 많다.

## 11. 유사 도구와의 비교

| 도구 | 강점 | 아티팩트와의 차이 |
|------|------|-------------------|
| ChatGPT Canvas | 장문 문서 협업 편집 | 아티팩트는 인터랙티브 출력(React·SVG·Mermaid·HTML 앱)에 강함 |
| Grok Studio | X/실시간 소셜 데이터 연동 | 아티팩트는 콘텐츠 유형·임베딩 지원이 넓음 |
| Claude Code | 로컬 실제 코드베이스를 수정하는 CLI/에이전트 | 아티팩트는 브라우저 기반 자립형 미리보기·공유 |
| Cursor Composer | 로컬 코드베이스를 풀 컨텍스트로 편집 | 아티팩트는 공유형 프로토타입에 적합 |

정리하면, 아티팩트는 **공유 가능한 인터랙티브 프로토타입과 도구**를 만드는 데 최적이고, 실제 코드베이스 수정이나 프로덕션 배포는 Claude Code/Cursor 등 전용 도구가 맡는다.

## 12. 실전 활용 시나리오

- **대시보드**: 데이터 스냅샷을 올려 W-o-W 변화가 표시되는 HTML 대시보드 생성
- **계산기·폼**: 예산 계산기, 신청 폼, 설문 도구
- **문서화**: 서식이 갖춰진 리포트, README, 가이드 문서
- **다이어그램**: 아키텍처·플로우를 Mermaid로 시각화
- **AI 마이크로앱**: 어학 튜터, 코드 리뷰어, PRD 작성기 등 Claude 지능을 내장한 앱
- **팀 생산성 도구**: 투표 도구, 회의록 템플릿(PDF/DOCX 내보내기 포함) 같은 단일 파일 웹 도구

## 13. 빠른 참조 (Quick Reference)

**활성화**: Settings(또는 Org settings) > Capabilities > Code execution and file creation 켜기

**생성**: 원하는 것을 설명 → 패널 자동 생성 → 후속 메시지로 수정

**보기 전환**: 패널 상단 Preview ↔ Code 토글

**공유**: 패널 하단 Publish → 링크 공유(계정 없이 열람, 계정 보유 시 리믹스)
