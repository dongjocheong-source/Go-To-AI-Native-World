AI Agent의 핵심 무기
Tool Calling(도구 호출) 완벽 가이드

"오늘 서울 날씨 어때?", "이메일 좀 보내줘" — LLM은 텍스트 창에 갇혀 실시간 데이터를 모르고, 실제로 메일을 보낼 수도 없습니다. 두뇌(AI)가 외부 세계와 상호작용할 수 있도록 '손과 발'을 달아주는 핵심 기술, Tool Calling을 정리합니다.

6단계 작동원리 날씨 에이전트 실습 RAG·파인튜닝과 비교
Overview

Tool Calling이란?

LLM이 사용자의 자연어 입력을 분석해, 목적 달성을 위해 미리 정의된 외부 도구(API, 함수, DB 검색 등)를 자율적으로 선택하고 실행할 수 있도록 하는 메커니즘입니다. LLM이 "어떤 도구를, 어떤 파라미터로 실행해야 하는지"를 JSON 형태의 구조화된 데이터로 출력합니다.

Function Calling과의 차이점

Function Calling

2023년 OpenAI가 처음 도입한 개념. 개발자가 정의한 '특정 함수'를 호출하도록 LLM이 인자값을 만들어주는 기능입니다.

Tool Calling (상위 개념)

Function Calling을 포함하는 상위 개념. 사용자 정의 함수뿐 아니라 웹 브라우징, 코드 실행기, 파일 시스템 접근 등 다양한 형태의 '도구'를 호출하는 현대적·확장된 개념입니다.

Architecture

핵심 구성요소

Tool Calling이 포함된 시스템은 다음 요소들이 유기적으로 맞물려 루프(Loop)를 형성합니다.

1
Tool Definition (도구 정의 스키마)"내가 가진 도구는 이런 것들이고, 이런 규칙으로 써야 해"를 알려주는 설명서. JSON Schema로 이름·설명·필수 입력값 등을 정의합니다.
2
LLM (추론 엔진)사용자 요청과 도구 정의서를 비교 분석해, 도구가 필요한지 판단하고 실행 파라미터를 생성합니다.
3
Tool Executor (도구 실행기)LLM이 반환한 JSON을 받아 실제로 코드를 실행하거나 외부 API를 호출하는 애플리케이션 백엔드 계층
4
Orchestrator (에이전트 루프)사용자 입력 → LLM의 도구 호출 판단 → 도구 실행 → 결과를 다시 LLM에 전달 → 최종 답변 생성의 전체 흐름을 제어
ReAct-based

작동 원리 (Step-by-Step)

ReAct(Reasoning + Acting) 패턴을 기반으로 한 Tool Calling의 흐름입니다.

  1. 사용자 요청 — "현재 애플(AAPL) 주가가 얼마야?"
  2. LLM의 추론(Thought) — "내 학습 데이터에는 실시간 주가 정보가 없네. get_stock_price 도구를 써야겠다. ticker: 'AAPL'로 설정하자."
  3. 도구 호출 요청(Action) — LLM이 텍스트 대신 {"name":"get_stock_price","arguments":{"ticker":"AAPL"}} JSON을 출력
  4. 도구 실행 — 오케스트레이터가 JSON을 가로채 실제 주가 조회 API를 실행
  5. 결과 관찰(Observation) — API 실행 결과(예: {"price":150.25})를 다시 LLM에 전달
  6. 최종 응답 생성 — "현재 애플의 주가는 $150.25입니다."
Trade-offs

특징 및 장단점

✅ 장점

·
LLM 능력의 무한한 확장실시간 검색, 복잡한 수학 연산, 파일 조작, 이메일·슬랙 연동이 가능해짐
·
환각 방지모르는 사실을 지어내는 대신 외부 도구(검색, RAG)로 검증된 팩트 기반 답변
·
모듈식 확장성재학습 없이 새 도구(API) 등록만으로 능력이 계속 늘어남

❌ 단점

·
비용 및 지연 시간 증가LLM→도구 실행→LLM의 여러 번 핑퐁(Round-trip)으로 응답 속도 저하, 토큰 비용 증가
·
보안 위험LLM이 생성한 파라미터로 실제 코드가 실행되므로, 프롬프트 인젝션으로 delete_all_data() 같은 도구가 실행될 위험. 철저한 입력 검증·샌드박싱 필수

[실습]

Python으로 Tool Calling 에이전트 직접 구축하기

OpenAI API로 LLM이 '날씨 조회 도구'를 스스로 판단하고 호출하는 완전한 Agent Loop를 구현합니다.

setup.sh
pip install openai python-dotenv
tool_calling_agent.py
import os, json
from openai import OpenAI

client = OpenAI(api_key=os.getenv("OPENAI_API_KEY"))

# 1. 실제 실행될 함수 (도구 구현)
def get_current_weather(location: str, unit: str = "celsius") -> str:
    # 실제로는 외부 날씨 API를 호출. 여기서는 모의 데이터 반환
    mock_db = {"서울": {"temperature": 22, "condition": "맑음"},
               "런던": {"temperature": 18, "condition": "비"}}
    info = mock_db.get(location, {"temperature": 20, "condition": "알 수 없음"})
    info["location"] = location; info["unit"] = unit
    return json.dumps(info, ensure_ascii=False)

# 2. 도구 명세서 (JSON Schema)
tools_definition = [{"type": "function", "function": {
    "name": "get_current_weather",
    "description": "특정 도시의 현재 날씨와 기온 정보를 가져옵니다.",
    "parameters": {"type": "object",
        "properties": {"location": {"type": "string"}, "unit": {"type": "string", "enum": ["celsius","fahrenheit"]}},
        "required": ["location"]}
}}]

# 3. 에이전트 루프 (Orchestrator)
def run_agent(user_prompt: str):
    messages = [{"role": "user", "content": user_prompt}]
    response = client.chat.completions.create(
        model="gpt-4o-mini", messages=messages,
        tools=tools_definition, tool_choice="auto"
    )
    msg = response.choices[0].message

    if msg.tool_calls:
        messages.append(msg)
        for tc in msg.tool_calls:
            args = json.loads(tc.function.arguments)
            result = get_current_weather(location=args.get("location"), unit=args.get("unit", "celsius"))
            messages.append({"tool_call_id": tc.id, "role": "tool",
                              "name": tc.function.name, "content": result})
        final = client.chat.completions.create(model="gpt-4o-mini", messages=messages)
        print(f"🤖 {final.choices[0].message.content}")
    else:
        print(f"🤖 {msg.content}")

run_agent("안녕! 넌 누구야?")        # 도구 호출 불필요
run_agent("지금 서울 날씨 어때?")     # 도구 호출 필요

At a Glance

한눈에 비교: Tool Calling vs RAG vs 파인튜닝

비교 항목Tool CallingRAGFine-Tuning
핵심 목적'행동(Action)'을 수행'지식(Knowledge)'을 참고'뇌 구조(가중치)' 자체를 변경
작동 방식API 호출, DB 쓰기, 코드 실행벡터 DB 검색 후 프롬프트에 삽입특정 도메인 데이터셋으로 재학습
데이터 실시간성최상 (실시간 API 즉시 조회)높음 (DB 업데이트 주기에 따름)낮음 (학습 시점에 고정)
주요 사용처날씨/주식 조회, 예약, 자동화사내 문서 검색, 매뉴얼 QA말투 학습, 도메인 용어 체득
상호 관계 — RAG 시스템을 실행하기 위한 '도구' 중 하나로 Tool Calling을 사용할 수 있습니다 (융합 가능).
Conclusion

마치며 — Tool Calling의 미래와 MCP

초기의 Tool Calling은 개발자가 하나하나 함수를 구현하고 LLM에 바인딩하는 복잡한 과정을 거쳐야 했습니다. 하지만 최근에는 MCP(Model Context Protocol)라는 새로운 오픈소스 표준이 등장했습니다.

01MCP를 활용하면 도구를 별도의 서버로 분리해, Claude든 GPT든 상관없이 "플러그 앤 플레이" 방식으로 도구를 손쉽게 공유·연동할 수 있습니다.
02Tool Calling은 LLM을 단순한 '말동무'에서 실질적인 비즈니스 가치를 창출하는 '디지털 노동자(AI Agent)'로 진화시키는 핵심 심장입니다.
기억할 것 한 줄 — AI 서비스 개발을 계획한다면, 프롬프트 엔지니어링을 넘어 Tool Calling 아키텍처 설계 역량은 선택이 아닌 필수입니다.
