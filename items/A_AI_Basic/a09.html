MCP (Model Context Protocol)란
AI를 위한 USB-C

LLM은 "학습 시점 이후는 모른다"와 "외부 세상과 단절되어 있다"는 두 가지 한계를 가집니다. AI 모델과 도구를 일일이 연결하는 M×N 문제를 해결하기 위해 Anthropic이 공개한 개방형 표준 프로토콜, MCP의 정의부터 아키텍처, 실습까지 정리합니다.

Host·Client·Server Resources·Tools·Prompts Python 실습 코드
Overview

MCP란 무엇인가

AI 모델(LLM)이 외부의 데이터(Data)나 도구(Tool)와 안전하게 상호작용할 수 있도록 돕는 개방형 표준 프로토콜입니다. AI에게 "이 데이터베이스를 읽는 법", "이 API를 실행하는 법"을 알려주는 공통된 언어이자 규약입니다.

마치 컴퓨터 주변기기를 연결할 때 제조사 상관없이 USB-C 하나로 통일하듯, AI 모델이 외부 데이터·시스템과 소통하는 방식을 표준화한 것입니다.

탄생 배경 — M×N 문제의 해결

기존에는 Claude용 도구, GPT용 도구, LangChain용 도구를 각각 따로 만들어야 했습니다.

기존 방식

AI 모델 3개 × 도구 10개

= 30개의 연동 코드가 필요합니다. 도구가 늘어날수록 관리가 불가능해집니다.

MCP 방식

도구를 MCP 표준으로 1번만

만들면, 모든 AI 모델에서 즉시 사용 가능합니다. AI가 로컬 파일, 사내 DB, Slack, GitHub 등과 자유롭게 연결됩니다.

Architecture

핵심 아키텍처 및 구성요소

전형적인 클라이언트-서버(Client-Server) 구조를 따르며, JSON-RPC 2.0 메시지 형식을 기반으로 통신합니다.

01
Host
LLM을 구동하는 최상위 애플리케이션. 사용자와 상호작용하는 인터페이스.

예: Claude Desktop, Cursor IDE, Zed Editor
→
02
Client
호스트 내부에서 서버와 1:1 연결을 유지하며 통신을 중재. 요청을 서버가 이해할 명령으로 변환하고 응답을 LLM에 전달.
→
03
Server
실제 데이터나 기능을 보유·제공. 외부 API 호출, DB 쿼리, 파일 읽기를 수행.

예: Google Drive, Slack, 로컬 파일시스템 서버

전송 계층 (Transport Layer)

Stdio

로컬 프로세스 간 통신. 빠르고 보안성이 높으며, 주로 로컬 도구용으로 사용됩니다.

SSE (Server-Sent Events)

HTTP 기반 통신. 원격 서버나 클라우드 서비스 연결에 사용됩니다.

3 Primitives

MCP의 3대 기능 요소

MCP 서버는 클라이언트(AI)에게 다음 세 가지 형태의 기능을 제공할 수 있습니다.

1 · 리소스 (Resources)

AI가 읽을 수 있는 데이터. 파일, DB 레코드, 로그 등이 해당됩니다 (Read-Only).

비유
  • 도서관의 책

2 · 도구 (Tools)

AI가 실행할 수 있는 함수. API 호출, 계산, 데이터 수정 등이 가능합니다 (Action).

비유
  • 계산기, 연장

3 · 프롬프트 (Prompts)

미리 정의된 지시문 템플릿. AI가 특정 작업을 더 잘 수행하도록 돕습니다.

비유
  • 업무 매뉴얼
Trade-offs

특징 및 장단점

✅ 장점

·
표준화된 연결한 번만 MCP 서버를 만들면 Claude, Cursor 등 다양한 AI 앱에서 즉시 사용 가능
·
데이터 보안로컬 우선(Local-first) 아키텍처 지원 — 민감한 데이터를 클라우드에 올리지 않고 로컬에서 분석
·
실시간성RAG처럼 벡터 DB를 구축할 필요 없이, 라이브 데이터에 직접 접근해 최신 정보를 가져옴
·
개발 생산성복잡한 인증이나 API 래퍼 코드를 매번 짤 필요가 없음

❌ 단점 및 한계

·
초기 단계표준이 정착되는 단계라 지원하는 호스트 앱이 아직 제한적 (Claude Desktop, Cursor 등)
·
보안 책임MCP는 연결 통로일 뿐 — 도구가 파일을 삭제하거나 정보를 유출하지 않도록 사용자 승인(Human-in-the-loop)이나 권한 관리 필수
·
인증 표준화 미비OAuth 같은 복잡한 인증 처리 표준 스펙이 아직 개발 중 (로드맵 포함)

[실습] End-to-End

Python으로 나만의 MCP 서버 구축하기

Python의 fastmcp 라이브러리로 "환율 계산기 & 날씨 조회" 기능을 제공하는 MCP 서버를 만들어, Claude Desktop에서 실제 도구처럼 사용해봅니다.

setup.sh
pip install mcp "fastmcp[cli]" httpx
my_server.py
from mcp.server.fastmcp import FastMCP
import httpx

# 1. MCP 서버 인스턴스 생성
mcp = FastMCP("My Utility Server")

# 2. 도구(Tool) 정의 - 환율 계산
@mcp.tool()
async def get_exchange_rate(base: str, target: str) -> str:
    # 현재 환율을 조회합니다. (base: 기준 통화 예: USD, target: 대상 통화 예: KRW)
    mock_rates = {"USD": {"KRW": 1450.5, "EUR": 0.92}, "KRW": {"USD": 0.00069}}
    rate = mock_rates.get(base, {}).get(target)
    if rate:
        return f"현재 {base} 1원은 {target} {rate}원 입니다."
    return f"{base}에서 {target}으로의 환율 정보를 찾을 수 없습니다."

# 3. 도구(Tool) 정의 - 날씨 예보
@mcp.tool()
async def get_weather_forecast(city: str) -> str:
    # 특정 도시의 날씨 예보를 조회합니다.
    weather_db = {"Seoul": "맑음, 22도", "New York": "비, 15도", "London": "흐림, 10도"}
    weather = weather_db.get(city, "알 수 없는 도시의 날씨입니다.")
    return f"{city}의 현재 날씨: {weather}"

# 4. 서버 실행
if __name__ == "__main__":
    mcp.run()

Claude Desktop에 서버 등록하기

macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
Windows: %APPDATA%\Claude\claude_desktop_config.json
claude_desktop_config.json
{
  "mcpServers": {
    "my-utility-server": {
      "command": "python",
      "args": ["/절대경로/my_server.py"]
    }
  }
}
주의 — args에는 my_server.py 파일의 절대 경로를 입력해야 합니다. python 명령어 경로 문제 시 uv나 가상환경의 python 경로를 사용하세요.

실행 및 테스트

  1. 설정 파일 저장 후 Claude Desktop 앱을 재실행
  2. 우측 상단에 🔌(플러그) 아이콘이 생기고 My Utility Server가 연결됨을 확인
  3. 채팅창에 질문: "서울 날씨 알려주고, 100달러가 한국 돈으로 얼마인지 계산해줘."
  4. 결과 — Claude가 스스로 get_weather_forecast와 get_exchange_rate 도구를 호출해 정확한 답변을 생성
At a Glance

한눈에 비교: 기존 API 연동 vs MCP

비교 항목기존 API/Function CallingMCP
연결 방식1:1 맞춤형 연동 (Point-to-Point)표준 프로토콜 기반 (Hub-and-Spoke)
구현 복잡도각 모델(OpenAI, Claude)마다 SDK 공부 필요한 번 만들면 모든 모델 호환
유지 보수도구 API 변경 시 모든 에이전트 수정 필요MCP 서버만 수정하면 끝
확장성낮음 — 도구가 늘어나면 관리 불가능높음 — 레고 블록처럼 추가 가능
통신 방향주로 단방향 (요청 → 응답)양방향 (지속적 연결, 상태 유지)
Conclusion

마치며

MCP는 AI가 단순히 "말만 잘하는 챗봇"에서 "실제 일을 수행하는 에이전트"로 진화하는 데 있어 가장 중요한 연결 고리(Missing Link)입니다.

01과거 웹의 발전이 HTTP라는 표준 프로토콜 덕분에 폭발했던 것처럼, AI 에이전트의 발전은 MCP 같은 표준 인터페이스를 통해 가속화될 것입니다.
02이제 개발자들은 "어떻게 연결할까"를 고민하는 대신, "어떤 가치 있는 데이터를 제공할까"에 집중할 수 있게 되었습니다.
기억할 것 한 줄 — 여러분도 지금 바로 MCP 서버를 구축해, 여러분만의 AI 에이전트에게 더 넓은 세상을 보여주세요.
