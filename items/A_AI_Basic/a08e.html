에이전틱 RAG (Agentic RAG)
검색 기계에서 자율적인 연구원으로

기존 RAG는 질문을 받으면 딱 한 번만 검색하고, 결과가 엉망이어도 그 틀 안에서만 답을 만듭니다. 에이전틱 RAG는 AI가 스스로 질문을 분석하고, 어떤 DB를 뒤질지 결정하며, 검색 결과가 부족하면 다시 검색하는 '자율적인 연구원'으로 진화한 아키텍처입니다.

기존 RAG = 수동적인 신입사원 · 에이전틱 RAG = 능동적인 수석 연구원
Overview

에이전틱 RAG란?

기존 RAG 파이프라인에 AI 에이전트의 자율적인 의사결정 능력과 도구 사용(Tool Use) 능력을 결합한 고도화된 아키텍처입니다.

기존 RAG · 수동적인 신입사원

"이 서랍(Vector DB)에서 자료 꺼내서 요약해"라고 하면 딱 그 서랍만 열어보고, 자료가 없어도 대충 얼버무립니다.

에이전틱 RAG · 능동적인 수석 연구원

"이건 사내 DB를 봐야겠군. 데이터가 부족하네? 인터넷 검색도 추가로 해봐야겠다. 이제 완벽하군, 보고서를 쓰자"라고 스스로 판단하고 행동합니다.

Core Components

핵심 구성요소 다섯 가지

이 5가지 요소가 톱니바퀴처럼 맞물려야 시스템이 작동합니다.

1
LLM (두뇌)시스템의 총괄 지휘자. 질문 의도를 파악하고 어떤 도구를 쓸지 결정하며 최종 답변을 생성합니다. (GPT-4o, Claude 3.5 등 도구 호출 능력이 뛰어난 모델 필수)
2
검색기 (Retriever)사내 문서·PDF 등을 벡터화해 저장한 Vector DB(Chroma, FAISS 등)에서 의미가 유사한 문서를 찾아옵니다.
3
도구 (Tools)에이전트가 활용할 무기들 — 벡터 DB 검색, 웹 검색(Tavily, Google), 사내 SQL DB 조회, 계산기, 코드 실행기 등을 쥐여줄 수 있습니다.
4
메모리 (Memory)이전 대화 맥락을 기억해 멀티턴(Multi-turn) 대화를 가능하게 합니다.
5
오케스트레이터 (Orchestrator)이 모든 과정을 제어하는 프레임워크. LangGraph, LlamaIndex, CrewAI 등이 에이전트의 반복 루프와 상태(State)를 관리합니다.
How It Works

작동 원리 및 아키텍처 패턴

고정된 순서가 아니라, 다음과 같은 순환적(Iterative) 흐름을 가집니다.

1
질문 분석 및 계획
복잡한 질문을 여러 하위 질문으로 쪼갬
→
2
도구 선택 및 실행
"질문 A는 사내 DB, 질문 B는 웹 검색"으로 스스로 라우팅
→
3
검색 결과 평가
찾아온 정보가 질문에 답하기 충분한지 팩트 체크 (Grader)
→
4
재검색
정보가 엉뚱하거나 부족하면 키워드를 수정해 다시 검색
→
5
답변 생성
충분한 정보가 모이면 최종 답변을 종합·출력
기존 RAG와의 가장 큰 차이 — 4단계 "재검색(Rewrite & Retrieve)" 루프입니다.

주요 아키텍처 패턴

라우터 패턴 (Router)

  • 질문 성격에 따라 가장 적합한 DB/도구 하나를 선택
  • 비교적 단순한 구조

멀티 에이전트 (Multi-Agent RAG)

  • '검색 전문', '분석 전문', '작성 전문' 에이전트가 역할 분담
  • 서로 대화하며 협업

CRAG (Corrective RAG)

  • 검색된 문서 품질을 AI가 스스로 평가
  • 관련성이 낮으면 웹 검색으로 지식 보완
Trade-offs

특징 및 장단점

✅ 장점

·
압도적인 정확도와 신뢰성검색 결과를 맹신하지 않고 스스로 평가·보완해 오답·할루시네이션이 획기적으로 줄어듦
·
복잡한 문제 해결 능력"올해 1분기 매출을 계산하고 작년과 비교해줘" 같은 다단계 추론도 처리
·
멀티 소스 통합사내 문서, 인터넷 뉴스, ERP 데이터를 유연하게 넘나들며 정보를 융합

❌ 단점 및 한계

·
느린 응답 속도여러 번 생각하고 검색하는 루프 → 답변까지 수 초~수십 초
·
비용(Token) 증가LLM을 여러 번 호출하므로 API 비용이 크게 증가
·
제어의 어려움자율성이 높은 만큼 무한 루프나 엉뚱한 도구 고집 등 예측 불가 행동 위험, 가드레일 필수
Use Cases

주요 활용 분야

방대한 데이터를 정밀하게 다뤄야 하는 엔터프라이즈 환경에서 빛을 발합니다.

고급 사내 지식 챗봇

  • 단순 매뉴얼 검색을 넘어
  • "에러 로그 분석 → 사내 위키에서 해결책 → 슬랙으로 요약본 발송" 같은 능동적 업무 수행

투자 및 금융 분석가

  • 실시간 주가 API + 수년간의 재무제표 PDF를 동시 분석
  • 종합적인 투자 리포트 생성

의료 · 법률 리서치 어시스턴트

  • 수만 건의 판례·의학 논문을 교차 검증
  • 모순 정보를 스스로 팩트체크, 정확한 근거 제시
[실습] LangChain

파이썬으로 에이전틱 RAG 구축하기

create_tool_calling_agent로 사내 문서(PDF) 검색 도구와 웹 검색 도구(Tavily)를 스스로 선택해 사용하는 에이전틱 RAG를 구현합니다.

setup.sh
pip install langchain langchain-openai langchain-community faiss-cpu pypdf
agentic_rag.py
import os
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_community.vectorstores import FAISS
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import PyMuPDFLoader
from langchain.tools.retriever import create_retriever_tool
from langchain_community.tools.tavily_search import TavilySearchResults
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_core.prompts import ChatPromptTemplate

def build_agentic_rag():
    # [1] 도구 1: 사내 문서(PDF) 검색 도구
    loader = PyMuPDFLoader("sample_company_policy.pdf")
    docs = loader.load()
    splitter = RecursiveCharacterTextSplitter(chunk_size=500)
    splits = splitter.split_documents(docs)
    vectorstore = FAISS.from_documents(splits, OpenAIEmbeddings())
    retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

    pdf_search_tool = create_retriever_tool(
        retriever, name="company_policy_search",
        description="사내 규정, 연차, 복지 정보를 찾을 때 이 도구를 사용하세요."
    )

    # [2] 도구 2: 실시간 웹 검색 도구
    web_search_tool = TavilySearchResults(k=3)
    tools = [pdf_search_tool, web_search_tool]

    # [3] 에이전트(두뇌) 및 프롬프트 설정
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
    prompt = ChatPromptTemplate.from_messages([
        ("system", "사내 정보는 company_policy_search를, 최신 외부 정보는 tavily 도구를 사용하세요. 부족하면 다시 검색하세요."),
        ("human", "{input}"),
        ("placeholder", "{agent_scratchpad}"),
    ])

    agent = create_tool_calling_agent(llm, tools, prompt)
    return AgentExecutor(agent=agent, tools=tools, verbose=True, max_iterations=5)

executor = build_agentic_rag()
response = executor.invoke({"input": "우리 회사 연차 규정을 알려주고, 2024년 AI 트렌드도 인터넷에서 찾아줘."})
print(response["output"])
실행 흐름 — verbose=True로 실행하면 AI가 "먼저 사내 규정 도구를 써서 연차를 찾고, 그다음 웹 검색 도구로 AI 트렌드를 찾아야겠다"라고 스스로 계획을 세우고 도구를 순차 호출하며 답변을 조합하는 사고 과정을 직접 볼 수 있습니다.
At a Glance

한눈에 비교: RAG vs Agent vs 에이전틱 RAG

에이전틱 RAG는 RAG와 Agent 엔지니어링이 완벽하게 결합된 결정체입니다.

구분RAG (Naive)AGENT에이전틱 RAG
핵심 목적가장 유사한 문서를 찾아 답변목표 달성 위해 자율적으로 도구 사용'완벽한 정보 검색과 답변 생성' 달성
작동 방식선형적 (질문→1회 검색→생성)순환적 (계획→도구→관찰→행동)반복적/적응형 (분석→선택→검색→평가·재검색→생성)
도구 활용지정된 단일 벡터 DB만웹검색·계산기·API 등 자유롭게여러 DB·웹·API를 '교차 검증' 목적으로 융합
비유서랍에서 서류 꺼내는 '수동적 인턴'법인카드 쥐고 알아서 뛰는 '독립적 실무자'다른 부서까지 뒤져 보고서 쓰는 '수석 연구원'
치명적 한계검색이 엉망이면 오답(할루시네이션)자유도가 높아 무한 루프 위험답변 속도 느리고 API 비용 비쌈
Conclusion

'검색'의 시대를 넘어 '자율 문제 해결'의 시대로

과거의 AI가 우리가 떠먹여 주는 데이터만 받아먹는 '수동적인 앵무새'였다면, 에이전틱 RAG가 적용된 AI는 도서관을 뒤지고 인터넷을 서핑하며 스스로 답을 찾아내는 '주도적인 파트너'로 진화했습니다.

01여러 번 생각하고 검색하느라 대답이 조금 느리고 API 비용이 발생한다는 단점이 있습니다.
02하지만 의료·금융·법률처럼 "절대 틀린 정보를 말해서는 안 되는" 환경에서는 비용과 속도를 희생하더라도 압도적인 정확도와 자율성이 선택이 아닌 필수가 되고 있습니다.
03여러분의 회사 문서와 다양한 API를 결합하면, 밤낮없이 스스로 문서를 읽고 고민하고 완벽한 보고서를 써내는 자율형 AI 비서를 만들 수 있습니다.
기억할 것 한 줄 — 속도·비용이 중요하면 Naive RAG, 정확도·자율성이 생명이면 에이전틱 RAG.
