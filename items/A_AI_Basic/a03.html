Overview

멀티모달 AI란 무엇인가

Multi(여러 개의) + Modality(양식·형태)의 합성어. 텍스트, 이미지, 음성 등 서로 다른 유형의 데이터를 결합해 정보를 처리하고 추론하는 인공지능 기술이다. 인간이 목소리 톤(청각)과 표정(시각), 말의 내용(언어)을 종합해 상대를 이해하듯, AI도 여러 감각을 융합(Fusion)해 맥락을 더 깊이 파악하는 것이 목표다.

유니모달 · Unimodal

텍스트 → 텍스트

단일 데이터 유형만 처리. 예: 초기 번역기, 텍스트 전용 챗봇. 텍스트 안의 정보만으로 판단하기 때문에 맥락 이해에 한계가 뚜렷하다.

멀티모달 · Multimodal

텍스트 + 이미지 → 텍스트

서로 다른 모달리티를 함께 입력받아 이해·생성. 예: 이미지 캡셔닝, 텍스트→이미지 생성(DALL·E). 시청각 정보를 통합해 훨씬 포괄적인 맥락을 파악한다.

핵심 철학 — "백문이 불여일견." 텍스트만으로 "노을 지는 해변"을 묘사하는 것보다 사진 한 장을 함께 주는 편이 정보 전달력이 훨씬 높다. 멀티모달 AI는 이 원리를 모델 내부에 그대로 옮겨온다.
Why It Emerged

왜 멀티모달 LLM이 필요한가

텍스트 기반 LLM은 토큰 시퀀스를 입력받아 다음 토큰을 예측하는 문자열 중심 모델이다. 하지만 현실 세계는 텍스트만으로 이루어져 있지 않다.

×
정보 손실이미지를 텍스트로 설명해서 입력하면 위치·색상·구조 같은 시각 정보의 세밀한 맥락이 사라진다.
×
현실 세계와의 괴리의료 영상 분석, 공장 센서 로그, UI 화면 해석 등 실제 산업 현장은 여러 모달리티를 동시에 해석해야 하는 경우가 대부분이다.

모달리티 갭(Modality Gap)

텍스트와 이미지·오디오는 표현되는 방식 자체가 다르다. 이 간극을 줄여 공통의 의미 공간으로 정렬하는 것이 멀티모달 모델의 핵심 과제다.

구분TEXTIMAGE / AUDIO
특성이산적(Discrete), 순차적(Sequential)연속적(Continuous), 공간적 / 시계열적
임베딩 공간문자열 기반의 의미 공간픽셀 / 파형 기반의 특징 공간
LLM 이전 시대의 한계 — 과거에는 이미지는 CNN, 텍스트는 RNN으로 각각 처리한 뒤 결과만 단순히 합쳤다(Early/Late Fusion). 모달리티가 늘수록 설계가 기하급수적으로 복잡해졌고, 의미 정렬이 부족했으며, VQA 같은 특정 태스크에만 특화되어 범용성이 떨어졌다.
Core Mechanics

서로 다른 데이터를 어떻게 하나로 합칠까

숫자로 된 텍스트 벡터와 픽셀로 된 이미지 벡터는 차원 자체가 다르다. 멀티모달 기술의 핵심은 이 이질적인 데이터를 특징으로 뽑아내고(인코딩), 같은 공간에 정렬한 뒤(임베딩 정렬), 적절한 시점에 섞는(융합) 것이다.

1 · 모달리티별 인코더

TEXT

Transformer

BERT, GPT 계열 모델이 문장을 의미 벡터로 변환한다.

IMAGE

CNN / ViT

ResNet 같은 CNN 또는 Vision Transformer가 이미지를 패치 단위 특징으로 추출한다.

AUDIO

Spectrogram + CNN/Transformer

음성을 스펙트로그램으로 변환한 뒤 CNN·Transformer로 특징을 뽑는다.

2 · 융합 전략(Fusion Strategies)

데이터를 합치는 시점에 따라 성능이 달라진다.

Early Fusion

입력 단계에서 바로 데이터를 합친다. 모달리티 간 상관관계가 높을 때 유리하다.

가장 많이 사용

Joint (Intermediate) Fusion

모델 중간 단계에서 Cross-Attention 등으로 서로의 정보를 교환하며 합친다. 오늘날 표준에 가깝다.

Late Fusion

각자 결과를 낸 뒤 투표(Voting)하거나 평균을 내어 합친다. 앙상블과 유사하다.

Turning Point

CLIP — 멀티모달 패러다임의 전환점

OpenAI가 제안한 CLIP(Contrastive Language-Image Pre-training)은 이미지와 텍스트를 하나의 임베딩 공간에 정렬하는 데 성공하며 현대 멀티모달 구조의 표준을 제시했다. "강아지"라는 텍스트 벡터와 강아지 사진의 이미지 벡터가 공간상에서 서로 가깝게 위치하도록 학습시키는 방식이다.

✓

Positive Pair · 일치 쌍

이미지와 그에 대응하는 텍스트 설명은 서로 가깝게 배치되도록 학습한다.

🐶 강아지 사진
"a dog"
×

Negative Pair · 불일치 쌍

관련 없는 이미지-텍스트 쌍은 서로 멀어지도록 학습한다.

🐶 강아지 사진
"a burger"
0

제로샷(Zero-shot) 능력 — 인터넷상의 수억 개 이미지-텍스트 쌍을 별도 정답 레이블 없이 대규모로 학습한 덕분에, 고정된 클래스 없이도 텍스트 설명만으로 새로운 개념을 인식할 수 있다. 이는 이후 LLM이 텍스트만으로 새 태스크를 수행하는 방식과 구조적으로 동일하다.

Modern Architecture

센서 · 다리 · 브레인 — 인코더-프로젝션-LLM 구조

현대 멀티모달 시스템은 효율성과 성능을 위해 인코더와 LLM을 분리하는 구조를 채택한다. 이미 잘 학습된 강력한 비전 인코더와 LLM을 결합하는 방식이 현재 가장 효율적인 실무적 해법이다.

01 · 센서
Vision Encoder
이미지를 임베딩 벡터로 변환. 주로 CLIP의 비전 인코더를 사용하며 "무엇을 보고 있는가"를 정의(인식)한다.
→
02 · 다리
Projection Layer
인코더의 출력을 LLM이 이해할 수 있는 토큰 임베딩 공간으로 변환하는 교량 역할을 한다.
→
03 · 브레인
LLM Backbone
변환된 정보를 바탕으로 최종 추론과 문장 생성을 수행. "그것에 대해 무엇을 할 것인가"를 결정(추론/생성)한다.
❄

Freeze 전략 — 대부분의 모델은 학습 시 비전 인코더를 가중치 고정(Freeze) 상태로 유지한다. 인코더가 이미 학습한 일반적인 시각 개념을 보존하기 위함이며, 다시 학습시키면 기존의 언어적 정렬 성질이 깨질 위험이 있다. 그래서 현대 멀티모달 설계의 핵심은 "인코더의 출력을 어떻게 LLM에 효율적으로 전달할 것인가"에 집중된다.

Trade-offs

장점과 단점

✅ 장점

01
높은 정확도와 맥락 이해텍스트만으로는 알 수 없는 뉘앙스(이미지 분위기, 목소리 톤)를 파악해 더 정확한 판단을 내린다.
02
UX 혁신글로 설명하지 않고 사진을 찍거나 말로 물어보는 직관적인 인터랙션이 가능하다.
03
새로운 창작 가능성텍스트로 이미지를 그리거나 영상을 보고 배경음악을 생성하는 등 창의적 작업이 가능하다.

❌ 단점

01
방대한 데이터 및 비용이미지·비디오는 텍스트보다 훨씬 커서 학습·추론 비용(GPU)이 매우 높다.
02
데이터 편향 및 품질 문제텍스트-이미지가 잘 매칭된 양질의 페어 데이터를 구하기 어렵다.
03
복잡성서로 다른 모달리티 간의 충돌·노이즈를 제어하는 아키텍처 설계가 까다롭다.

직접 해보기 — BLIP & CLIP

Hugging Face의 transformers 라이브러리로 두 가지를 실습해본다. 이미지를 설명문으로 바꾸는 이미지 캡셔닝(BLIP)과, 텍스트-이미지 유사도를 계산하는 CLIP이다. CPU에서도 동작한다.

IMAGE 이미지 캡셔닝 (BLIP)

caption.py
import requests
from PIL import Image
from transformers import BlipProcessor, BlipForConditionalGeneration

# 1. 모델 및 프로세서 로드 (Salesforce의 BLIP 모델 사용)
processor = BlipProcessor.from_pretrained("Salesforce/blip-image-captioning-base")
model = BlipForConditionalGeneration.from_pretrained("Salesforce/blip-image-captioning-base")

# 2. 이미지 준비 (URL에서 로드)
img_url = 'https://storage.googleapis.com/sfr-vision-language-research/BLIP/demo.jpg'
raw_image = Image.open(requests.get(img_url, stream=True).raw).convert('RGB')

# 3. 데이터 전처리 — 텍스트 힌트를 주면 더 정확한 캡션을 생성
text = "a photography of"
inputs = processor(raw_image, text, return_tensors="pt")

# 4. 추론 (Caption Generation)
out = model.generate(**inputs, max_new_tokens=50)

# 5. 결과 디코딩
caption = processor.decode(out[0], skip_special_tokens=True)
print(f"👉 {caption}")
▶ a photography of a woman and her dog on the beach

CLIP 텍스트로 이미지 검색하기

clip_search.py
from transformers import CLIPProcessor, CLIPModel

# 1. CLIP 모델 로드
model = CLIPModel.from_pretrained("openai/clip-vit-base-patch32")
processor = CLIPProcessor.from_pretrained("openai/clip-vit-base-patch32")

# 2. 후보 텍스트 준비 (raw_image는 위 예제의 해변 사진 재사용)
candidates = ["a dog playing", "a cat sleeping", "a delicious burger"]

# 3. 입력 처리 및 추론
inputs = processor(text=candidates, images=raw_image, return_tensors="pt", padding=True)
outputs = model(**inputs)

# 4. 유사도 계산 (Logits → Softmax)
logits_per_image = outputs.logits_per_image
probs = logits_per_image.softmax(dim=1)

# 5. 결과 출력
for i, prob in enumerate(probs[0]):
    print(f"'{candidates[i]}': {prob.item()*100:.2f}%")
▶ 'a dog playing': 98.50%
  'a cat sleeping': 0.10%
  'a delicious burger': 1.40%

Summary

세 문장으로 정리하는 멀티모달 LLM

인간이 보고 듣고 이해하듯, AI도 여러 감각을 하나의 인지 공간에서 통합하는 방향으로 진화하고 있다.

01현실 세계를 제대로 이해하려면 텍스트만으로는 부족하다 — 위치·색상·톤 같은 정보는 언어로 온전히 옮겨지지 않는다.
02서로 다른 데이터를 하나의 의미 공간으로 정렬하는 것이 관건이며, CLIP이 대조 학습으로 그 표준을 제시했다.
03현대 아키텍처는 인코더(센서) + 프로젝션 레이어(다리) + LLM(브레인)의 분업 구조로 효율성과 확장성을 동시에 확보한다.
