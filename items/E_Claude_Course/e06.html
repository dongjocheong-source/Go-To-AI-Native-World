Introduction to Model Context Protocol · Onboarding

통합 코드 없이
Claude를 외부 세계에 연결하기

Model Context Protocol(MCP)은 Claude를 외부 서비스·데이터 소스에 연결할 때 지루한 통합 코드를 없애주는 개방형 표준입니다. 핵심 아키텍처 이해부터 Python SDK로 첫 MCP 서버 만들기, 클라이언트에서 리소스·프롬프트 연동하기까지 4개 모듈·10개 레슨을 정리했습니다.

Module 01 · Get Started

MCP란 무엇인가

MCP는 AI 모델이 외부 시스템과 상호작용하는 방식을 표준화합니다. 서비스마다 직접 통합 코드를 짜는 대신, 한 번 표준을 따르면 여러 클라이언트·서버가 서로 호환됩니다.

🧩 무엇을 해결하나

  • 서비스마다 제각각인 통합 코드 문제
  • 툴 정의·실행 부담을 전문 MCP 서버로 이전

🔗 세 주체

  • Host — Claude Desktop·Code 등 사용자 앱
  • Client — 서버와 통신하는 연결부
  • Server — 실제 툴·데이터를 노출하는 쪽

🚚 전송 방식

  • STDIO — 로컬 개발, 서브프로세스로 실행
  • HTTP+SSE — 원격 배포, HTTP 서비스로 실행
핵심 — MCP 클라이언트가 서버와 통신하는 방식, 요청이 사용자 질문에서 외부 서비스를 거쳐 다시 Claude에게 돌아오는 전체 흐름부터 익힙니다.
Message Flow

요청 → 서버 → 응답의 전체 흐름

사용자의 질문이 Claude에게 도달해 실제 답으로 돌아오기까지, MCP는 다음 흐름을 거칩니다.

STEP 01
사용자 질문
Claude가 답하려면 외부 데이터·행동이 필요한 요청
→
STEP 02
MCP Client
연결된 MCP 서버에 요청을 전달
→
STEP 03
MCP Server
외부 서비스를 호출해 실제 작업을 수행
→
STEP 04
Claude에 반영
결과가 다시 Claude에게 전달되어 응답으로 완성
MCP Inspector — 서버 구현을 직접 확인할 수 있는 공식 도구입니다. 실습 과정에서 정의한 툴·리소스·프롬프트가 의도대로 동작하는지 이 인스펙터로 테스트합니다.
Module 02 · Build a Server

처음부터 MCP 서버 만들기

Python 프로젝트를 설정하고, 데코레이터로 툴을 정의하며, 공식 인스펙터로 테스트합니다.

Python SDK · 데코레이터
JSON 스키마를 직접 작성하는 대신 데코레이터로 툴을 정의합니다. 함수 시그니처와 타입 힌트만으로 Claude가 이해할 수 있는 툴이 만들어집니다.
Field 설명 & 타입 힌트
문서 읽기·편집 같은 기능을 구현할 때, Field 설명과 타입 힌트로 각 매개변수가 무엇인지 Claude에게 명확히 전달합니다.
MCP Inspector로 테스트
서버를 실행하고 인스펙터에 연결해, 정의한 툴이 예상대로 호출·응답하는지 확인합니다.
# Python SDK로 툴 정의하기 (개념 예시)
@mcp.tool()
def read_document(name: str) -> str:
  """이름으로 문서를 읽어 내용을 반환합니다."""
  return documents[name]
Module 03 · Client, Resources & Prompts

클라이언트 구현 & 리소스·프롬프트 연동

서버에 연결하는 MCP 클라이언트를 구현하고, 리소스를 정의·접근하며 프롬프트를 다루는 법을 배워 완전한 애플리케이션으로 통합합니다.

Resources

GET처럼 읽기

일반 HTTP 서버의 GET 핸들러와 비슷하게 데이터를 노출합니다. 행동을 수행하기보다 정보를 가져와야 할 때 적합합니다. 예: @문서이름 자동완성 기능.

Reading Resources

MIME 타입 처리

클라이언트에서 리소스를 읽을 때 JSON·텍스트 콘텐츠의 MIME 타입을 올바르게 처리하는 구현 패턴을 다룹니다.

Prompts

미리 완성된 워크플로우

문서 포맷팅처럼 흔한 작업에 미리 잘 만들어진 고품질 지침을 제공하는 프롬프트를 구성합니다.

실전 예 — 사용자가 @문서이름을 입력하면, 자동완성을 위해 사용 가능한 문서 목록을 가져오고, 특정 문서가 멘션되면 해당 문서 내용을 가져옵니다. 이때 문서 내용이 프롬프트에 자동으로 주입되어, Claude가 굳이 툴을 호출해 정보를 가져올 필요가 없어집니다.
Wrap-up · Module 04

세 가지 기본 요소, 언제 무엇을 쓸까

MCP의 세 primitive는 누가 통제하는가가 다릅니다. 이 차이를 이해하는 것이 강좌 전체를 관통하는 핵심입니다.

구분 Tools Resources Prompts
누가 통제 모델이 통제 (model-controlled) 애플리케이션이 통제 (app-controlled) 사용자가 통제 (user-controlled)
패턴 Claude가 자율적으로 호출 요청-응답으로 데이터를 가져옴 사용자가 워크플로우를 선택해 실행
비유 행동을 수행하는 함수 HTTP GET 핸들러 미리 작성된 슬래시 명령
행동이 필요하면 Tools 정보만 가져오면 Resources 정형화된 워크플로우는 Prompts
Conclusion

마치며

MCP는 Claude를 "매번 새로 통합 코드를 짜지 않고" 외부 세계에 연결하는 개방형 표준입니다. 서버와 클라이언트를 모두 만들어보면 AI 모델과 외부 서비스가 어떻게 매끄럽게 통신하는지 완전히 이해하게 됩니다.
