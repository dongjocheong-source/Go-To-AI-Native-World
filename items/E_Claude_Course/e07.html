01 · Sampling

샘플링 — 서버가 클라이언트에 LLM 호출을 요청하다

MCP 서버가 연결된 클라이언트를 통해 언어 모델 호출 자체를 요청할 수 있게 해주는 기능입니다. AI 비용과 복잡도를 서버에서 클라이언트로 옮깁니다.

왜 필요한가
서버가 자체적으로 LLM API 키·비용을 부담하는 대신, 이미 연결되어 있는 클라이언트의 모델 접근권을 빌려 씁니다.
sampling/createMessage
서버→클라이언트 방향의 primitive로, 재귀적인 에이전트 워크플로우를 가능하게 합니다 — 예: PR 설명이나 릴리스 노트를 서버가 모델에게 직접 초안 요청.
비용·복잡도 이동
AI 관련 비용과 복잡도의 책임 소재를 서버에서 클라이언트 쪽으로 옮기는 설계 패턴입니다.

03 · Roots

Roots — 안전하고 사용자 친화적인 파일 접근

Roots는 MCP 서버에 로컬 머신의 특정 파일·폴더 접근 권한을 부여하는 방법입니다. 단순한 권한 부여를 넘어, 사용자 경험 문제까지 함께 해결합니다.

문제
전체 경로가 필요함
"biking.mp4를 변환해줘"라고만 하면 Claude는 파일이 어디 있는지 검색할 방법이 없음
→
해결 1
Roots로 범위 지정
"이 폴더는 접근 가능"이라는 범위를 미리 지정해두면 자동으로 파일을 찾음
→
해결 2
보안 경계
Desktop 폴더만 허용하면 Documents·Downloads 등 다른 위치는 접근 불가
→
결과
사용자 친화적 + 안전
전체 경로를 입력할 필요 없이, 허용된 범위 밖 파일은 오류로 안내
유의 — MCP SDK가 루트를 자동으로 강제하지는 않습니다. 서버 구현이 직접 접근 범위를 검사해야 하며, 승인되지 않은 위치의 파일에 접근하려 하면 사용자에게 "현재 서버 설정에서는 접근할 수 없다"고 안내해야 합니다.
04 · Module 2 · Message Layer

JSON 메시지 아키텍처

MCP 메시지가 클라이언트·서버 사이를 어떻게 오가는지 이해합니다. 요청-응답 쌍과 알림(notification) 메시지를 구분하고, 양방향 통신 패턴을 다룹니다.

Request-Result Pairs
tools/call, resources/read, prompts/get, sampling/createMessage 등 — 요청을 보내면 반드시 대응하는 결과가 돌아옵니다.
Notifications
listChanged, progress 등 — 응답을 기대하지 않는 일방향 업데이트 메시지입니다.
양방향 통신
클라이언트→서버, 서버→클라이언트 양쪽 방향 모두에서 메시지가 오갈 수 있다는 점이 MCP를 단순 API 호출과 구분 짓습니다.
05 · Transport Mechanisms

STDIO & StreamableHTTP — 언제 무엇을 쓸까

로컬 개발과 원격 배포, 상황에 맞는 전송 방식을 선택하는 법을 다룹니다.

Local

STDIO 전송

표준 입출력 스트림으로 통신하며, 시작 시 초기화 핸드셰이크 과정을 거칩니다. 로컬 개발용으로 간단하고 직관적입니다.

Remote

StreamableHTTP 전송

Server-Sent Events(SSE)로 서버→클라이언트 통신을 HTTP 위에서 구현합니다. 세션 관리와 이중 연결 구조가 필요해 STDIO보다 복잡합니다.

기준 STDIO StreamableHTTP
적합한 상황 로컬 개발 원격 배포
설정 플래그 영향 해당 없음 서버 발신 요청·스트리밍 기능에 영향
스케일링 단일 프로세스 로드밸런서와 수평 확장(stateless) 가능
트레이드오프 - Stateful vs Stateless 선택 필요
프로덕션 스케일링 — 로드밸런서와 함께 수평 확장하려면 Stateless HTTP를 고려하세요. Stateful 구성은 더 많은 기능을 제공하지만 확장성과 맞바꿔야 할 수 있습니다. 배포 요건·기능 필요성·스케일링 제약에 따라 전송 방식을 선택하는 기준을 강좌 마지막에 정리합니다.
Conclusion

마치며

기본기를 넘어선 MCP는 "서버가 얼마나 똑똑하고 안전하게, 또 얼마나 크게 확장될 수 있는가"의 문제입니다. 샘플링·알림·Roots가 기능적 강력함을, 메시지 구조와 전송 계층이 프로덕션 안정성을 책임집니다.
