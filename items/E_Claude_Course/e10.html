한 번 적어두면,
Claude가 매번 알아서 씁니다

매번 같은 지침을 프롬프트에 붙여넣는 대신, 요청이 일치할 때 Claude Code가 자동으로 읽어들이는 곳에 한 번 적어두는 것 — 그게 스킬입니다. 첫 SKILL.md 작성부터 트리거되는 설명 쓰기, 툴 접근 제한, 점진적 공개로 큰 스킬 조직화하기, 다른 커스터마이징 도구와 비교하기, 팀 공유와 트러블슈팅까지 6개 레슨을 정리했습니다.

01 · What Are Skills

스킬이란 무엇인가

스킬은 Claude Code가 특정 작업을 더 정확하게 처리하도록 찾아 쓸 수 있는 지침 폴더입니다. 매번 같은 가이드를 반복해 붙여넣는 대신, 한 번 적어두면 관련 요청이 올 때마다 자동으로 적용됩니다.

📄 구조

  • 각 스킬은 SKILL.md 파일 하나
  • YAML 프론트매터에 이름·설명 명시

🎯 매칭 방식

  • 요청이 오면 설명(description)과 대조
  • 일치하는 스킬을 Claude가 자동으로 로드

📂 저장 위치

  • 개인(personal) 디렉토리 — 내 모든 프로젝트
  • 프로젝트(project) 디렉토리 — 해당 저장소만
핵심 — PR을 리뷰해달라거나 커밋 메시지를 써달라고 할 때마다 지침을 반복하는 대신, 한 번 스킬로 적어두면 그 작업이 나올 때마다 Claude가 일관되게 적용합니다.
02 · Creating Your First Skill

처음부터 스킬 만들기

유효한 SKILL.md 프론트매터로 스킬을 만들고, 실제로 로드되는지 확인하는 법을 배웁니다.

---
name: commit-message
description: Use when writing a git commit message.
  Follows the team's conventional-commits style with scope and body.
---

# Commit message convention
Format: type(scope): summary — imperative mood, under 50 chars...
확인 — 스킬을 저장한 뒤, 관련 작업을 요청해 Claude가 실제로 그 스킬을 불러와 적용하는지 확인하는 것이 이 레슨의 실습 핵심입니다.
03 · Descriptions & Tool Access

트리거 잘 되는 설명 쓰기 & 툴 접근 제한

스킬이 언제 실행될지는 전적으로 description의 품질에 달려 있습니다. 너무 좁으면 트리거가 안 되고, 너무 넓으면 원치 않을 때도 끼어듭니다.

Effective Description

효과적인 설명 작성

"언제 사용하는지"를 구체적으로 명시합니다. 막연한 카테고리명보다, 실제 요청과 겹치는 상황·트리거 문구를 설명에 담을수록 매칭이 정확해집니다.

allowed-tools

툴 접근 제한

스킬이 사용할 수 있는 도구를 명시적으로 제한해, 의도치 않은 파일 수정이나 명령 실행 범위를 좁힙니다.

04 · Organizing Larger Skills

점진적 공개(Progressive Disclosure)로 큰 스킬 조직화하기

스킬이 커지면 모든 내용을 한 파일에 욱여넣는 대신, 필요할 때만 단계적으로 세부 내용을 불러오는 구조로 나눕니다.

SKILL.md

진입점

가장 자주 필요한 핵심 지침만 담아 가볍게 유지합니다.

참조 파일

Reference Files

상세 규칙·예외 케이스는 별도 파일로 분리해, 필요할 때만 Claude가 열어봅니다.

실행 스크립트

Executable Scripts

반복적인 검증·변환 로직은 스크립트로 분리해 스킬이 직접 실행하게 합니다.

왜 중요한가 — 모든 내용을 한 번에 로드하면 컨텍스트가 낭비됩니다. 점진적 공개는 컨텍스트 효율성을 지키면서도 큰 스킬을 다룰 수 있게 해줍니다.
05 · Choosing the Right Tool

스킬 vs CLAUDE.md vs 서브에이전트 vs 훅 vs MCP

같은 문제도 여러 커스터마이징 도구로 풀 수 있습니다. 어떤 상황에 무엇을 골라야 할지가 이 레슨의 핵심입니다.

Skill
스킬

특정 작업 유형에 조건부로 적용되는 재사용 지침. 요청이 일치할 때만 로드.

CLAUDE.md
항상 로드

세션마다 항상 읽히는 프로젝트 전역 컨텍스트. 모든 작업에 적용되는 규칙에 적합.

Subagent
서브에이전트

별도 컨텍스트 윈도우가 필요한, 격리된 전문 작업에 적합.

Hook
훅

예외 없이 강제되어야 하는 규칙 — 조언이 아니라 결정론적 통제가 필요할 때.

MCP
MCP 서버

외부 시스템과의 연결이 필요할 때 — 데이터·툴을 가져오는 문제.

조건부 반복 작업 → Skill 항상 적용될 규칙 → CLAUDE.md 격리된 전문 작업 → Subagent 예외 없는 강제 → Hook 외부 연결 → MCP
06 · Share & Troubleshoot

팀과 공유하고 문제를 진단하기

잘 만든 스킬 하나는 팀 전체의 표준이 될 수 있습니다. 배포 방법과, 스킬이 예상대로 동작하지 않을 때의 진단 체크리스트를 다룹니다.

프로젝트 저장소
스킬 파일을 레포지토리에 커밋해, 저장소를 체크아웃하는 모든 팀원이 자동으로 같은 스킬을 사용하게 합니다.
플러그인(Plugins)
여러 스킬·커넥터·명령을 묶어 설치형 패키지로 배포합니다.
엔터프라이즈 관리 설정
조직 차원에서 강제로 배포되는 관리형 설정을 통해 스킬을 전사에 적용합니다.
커스텀 서브에이전트와 결합
스킬을 서브에이전트에 연결해, 격리된 컨텍스트에서 전문화된 작업을 수행하게 합니다.
트러블슈팅 체크리스트 — 스킬이 동작하지 않을 때는 ① 트리거링 문제(설명이 요청과 매칭되지 않음) ② 로딩 문제(파일 경로·프론트매터 오류) ③ 우선순위 충돌(여러 스킬이 겹침) ④ 런타임 오류 순으로 확인합니다. claude --debug와 스킬 검증기(skills validator)로 각 단계를 진단합니다.
Conclusion

마치며

스킬은 "반복을 멈추고 한 번만 가르치는" 방법입니다. 매 프롬프트에 같은 가이드를 붙여넣는 대신, Claude Code가 자동으로 읽는 곳에 적어두면 매번 일관되게 적용됩니다.

01SKILL.md 프론트매터로 이름·설명을 정의하고, 실제로 트리거되는지 확인하며 첫 스킬을 만드세요.
02설명은 구체적으로 쓰고 allowed-tools로 범위를 제한하며, 큰 스킬은 점진적 공개로 나누세요.
03CLAUDE.md·서브에이전트·훅·MCP와 비교해 적합한 도구를 고르고, 레포·플러그인·관리형 설정으로 팀에 공유하세요.
다음 단계 — 최근 반복해서 설명했던 작업(커밋 메시지, PR 리뷰, 문서 템플릿 등) 하나를 골라 SKILL.md로 만들어보고, 다음 세션에서 자동으로 트리거되는지 확인해보세요.
