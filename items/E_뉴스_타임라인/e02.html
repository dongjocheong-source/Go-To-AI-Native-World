Andrej Karpathy가 제안한 "LLM을 활용한 개인 지식 베이스 구축 패턴"입니다. 검색할 때마다 문서를 다시 뒤지는 RAG와 달리, LLM이 자료를 읽고 정리하고 연결하며 시간이 지날수록 스스로 성장하는 지식 운영체제(Knowledge OS)를 만드는 접근입니다. 이 문서는 완성된 소프트웨어가 아니라, LLM Agent(Codex, Claude Code 등)에게 그대로 전달해 자신만의 Knowledge Wiki를 구축하도록 하는 설계 아이디어 파일입니다.

1. 핵심 배경 — 기존 RAG의 한계

일반적인 LLM 문서 활용 방식은 RAG(Retrieval Augmented Generation)입니다. 문서를 업로드하면 질문 시점에 관련 내용을 검색하고 답변을 생성합니다.

하지만 Karpathy가 지적하는 문제는 "지식의 축적이 없다"는 점입니다. 질문할 때마다 LLM은 원본 문서에서 다시 정보를 찾고 조합해야 하며, 이전 분석 결과나 문서 간 관계가 지속적으로 쌓이지 않습니다.

2. 핵심 아이디어 — LLM을 지식 관리자로

LLM Wiki는 검색 시스템이 아니라 "지식을 컴파일하고 유지하는 시스템"입니다. 기존에는 사람이 논문을 읽고 노트를 작성하고 폴더를 정리했다면, 이 방식에서는 LLM이 다음 과정을 대신 수행합니다.

  • 원본 자료를 읽는다
  • 핵심 정보를 추출한다
  • 기존 Wiki 구조와 연결한다
  • 새로운 정보와 기존 지식을 통합한다
  • 모순이나 변경 사항을 기록한다

사용자는 연구 방향과 질문에 집중하고, LLM은 지식 구조화·요약·연결·정리를 담당합니다. 결과적으로 Wiki는 시간이 지날수록 풍부해지는 지속 가능한 지식 자산이 됩니다.

3. 전체 Knowledge Pipeline

Raw Data

논문, 기사, Repo, 데이터셋, 이미지 등 원본 자료 저장

Ingest

웹 자료를 Markdown으로 변환하고 이미지 확보

Compile

LLM이 Wiki 문서와 개념 구조 생성

Query

LLM Agent가 축적된 지식 기반 질문 수행

Improve

결과를 다시 Wiki에 추가하여 성장

4. Persistent Wiki 구축 방식

문서 요약 (Compilation)

새 문서가 추가될 때 단순히 색인하지 않습니다. LLM이 긴 논문과 기술 문서를 읽고 핵심 내용 중심의 Markdown Article로 변환하여 기존 지식 구조에 반영합니다.

Concept Organization & Connection

비슷한 주제를 묶어 새로운 개념 문서를 생성하고, Entity Page·Topic Summary·Backlink를 만들어 문서 사이의 관계를 Knowledge Graph 형태로 유지·확장합니다.

Knowledge Growth

새로운 자료와 질문이 추가될수록 Wiki가 점점 더 정교해집니다. 색인이 아니라 지식 그 자체가 누적되고 다듬어지는 구조입니다.

5. Obsidian 기반 Knowledge IDE

Obsidian은 단순한 메모 앱이 아니라 생성된 Wiki를 탐색하는 인터페이스 역할을 합니다. Raw 데이터, LLM이 만든 문서, 이미지, 분석 결과, 시각화 자료를 한 곳에서 관리합니다.

  • Markdown 기반 데이터 저장
  • 문서 간 Link 탐색
  • Marp를 활용한 Presentation 생성
  • 이미지와 분석 결과 관리

6. Idea File라는 공유 방식

Karpathy는 완성된 코드보다 "아이디어 파일"을 공유하는 새로운 방식을 제안합니다.

사용자는 이 문서를 자신의 LLM Agent(Codex, Claude Code 등)에 전달하고, Agent가 자신의 환경에 맞는 LLM Wiki를 직접 구현하도록 합니다. 정형화된 소프트웨어를 그대로 설치하는 대신, 아이디어를 이해한 Agent가 맥락에 맞게 재구성하는 셈입니다.

7. Q&A Agent 활용 — 실제 규모

Knowledge Base가 충분히 쌓이면 LLM Agent는 단순 검색을 넘어 복합적인 연구 질문을 처리할 수 있습니다. Karpathy는 다음과 같은 규모의 Wiki에서, 별도의 복잡한 RAG 없이도 LLM이 관련 자료를 스스로 찾아 답변하는 경험을 공유했습니다.

8. 지속적인 Knowledge Improvement

  • 문서 간 데이터 불일치 검사
  • 빠진 정보 탐색 및 보완
  • 새로운 연구 질문 제안
  • 흥미로운 개념 연결 발견
  • 검색 도구를 LLM Agent Tool로 활용

9. 활용 예시

  • 개인 연구 Knowledge Base
  • 논문 및 기술 자료 관리
  • 기업 내부 지식 Wiki
  • 프로젝트 히스토리 관리
  • 지속적으로 성장하는 AI Research Assistant

10. Future Direction

장기적으로는 축적된 Knowledge Base를 활용하여 Synthetic Data를 생성하고, Fine-tuning을 통해 LLM 자체가 개인 연구 지식을 내재화하는 방향으로 발전할 수 있습니다.

11. 기존 방식과 비교 — RAG vs LLM Wiki

RAGLLM Wiki
질문마다 검색지식 사전 컴파일
매번 새롭게 조합기존 지식 활용
축적 효과 제한시간에 따라 성장

Summary

LLM Knowledge Base는 "문서를 저장하는 시스템"이 아니라, AI가 읽고 이해하고 연결하며 성장하는 개인 연구 운영체제입니다.

Research → Knowledge Compilation → AI Q&A → New Insight → Knowledge Growth 라는 순환 구조가 핵심입니다.
