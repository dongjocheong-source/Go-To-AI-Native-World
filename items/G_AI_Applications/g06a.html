좋은 프로토타입은
좋은 PRD에서 시작된다

PRD(Product Requirement Document)는 바이브코딩의 첫 단계이자 가장 중요한 기초입니다. PRD Agent 구성부터 UI Designer Prompt, 실제 PRD 예제까지 전 과정을 정리했습니다.

1~2페이지면 충분 PRD Agent 시스템 프롬프트 템플릿 바로 쓰기
Why PRD

AI 개발과정에서 PRD의 3가지 핵심 역할

1
프로젝트 목표와 범위 명확화"좋은 대시보드를 만들어줘" 같은 모호한 요청은 반복 수정을 부릅니다. "뉴스 RSS를 AI로 요약하고 검색 필터가 있는 대시보드"처럼 구체화하면 한 번에 원하는 결과에 가까워집니다.
2
AI 코드의 일관된 방향성 제공"개발환경: Python/Streamlit, API: Gauss Chat API" 처럼 기술 스택을 PRD에 명시하면, 에이전트가 그 스택으로만 코드를 생성해 구조가 통일되고 유지보수가 쉬워집니다.
3
컨텍스트 파일 기반 (Context as Code)PRD를 시스템 프롬프트에 포함시키면 모든 대화에서 일관된 맥락이 유지되고, 프로젝트 세부사항이 자동으로 반영되어 휴먼 에러가 줄어듭니다.
Traditional vs Vibe

전통적인 PRD vs 바이브코딩 PRD

📖 전통적인 PRD

완벽한 완성도가 목표. 개요·배경·목표/KPI·대상사용자·기능요구사항·비기능요구사항·제약사항·범위·릴리스계획까지 전부 포함. 30~50페이지 이상, 작성에 수주 소요, 팀 전체 합의 필요.

⚡ 바이브코딩 PRD

AI가 참고할 핵심 기준이 목표. 제품개요·핵심기능(5개 이내)·대상사용자·기술스택 중심. 1~2페이지, 작성에 30분 이내, AI 입력용으로 최적화.

📖 전통적인 PRD를 쓰는 경우
  • 대규모 팀 프로젝트
  • 장기 개발 프로젝트
  • 복잡한 요구사항
  • 여러 이해관계자 조율
⚡ 바이브코딩 PRD를 쓰는 경우
  • 빠른 프로토타입 개발
  • AI 기반 개발
  • 개인 또는 소규모 팀
  • 초기 아이디어 검증 · MVP 개발
Process

바이브코딩 6단계 프로세스

1단계
아이디어 수집
만들고 싶은 것에 대한 막연한 생각에서 시작합니다.
2단계
PRD Agent와 인터뷰
체크리스트 기반으로 한 번에 1개씩 질문받으며 요구사항을 정리합니다.
3단계
PRD 초안 작성
마크다운 형식으로 자동 생성되고, 필요시 Mermaid 차트도 포함됩니다.
4단계
UI Designer Prompt 활용
개발 환경, 레이아웃, 입력 방식, API 참조 코드를 선택합니다.
5단계
프로토타입 코드 생성
선택한 개발 환경에 맞는 코드와 파일 구조가 자동 생성됩니다.
6단계
프로토타입 완성
개발 준비가 끝난 상태입니다.
PRD Agent

PRD Agent 구성 — 인터뷰형 시스템 프롬프트

한 번에 문서를 전부 쓰지 않고, 필요한 내용을 하나씩 질문하며 PRD를 완성해가는 에이전트입니다.

PRD Agent 시스템 프롬프트
# 역할
- 사용자의 요구를 단계적으로 확인하면서 PRD를 완성한다.
- 매턴마다 질문은 반드시 1개만 한다.
- 중간중간 확보한 항목을 체크리스트로 보여준다.
- 정보가 충분해지면 PRD 초안을 작성한다.

# 규칙
- 이미 확인한 내용은 다시 묻지 않는다.
- 불명확한 내용은 추정하지 말고 확인 필요로 남긴다.
- 충분한 정보가 모이기 전에는 PRD 전체를 작성하지 않는다.
- 완성된 PRD는 markdown code 형식으로 출력한다.

# 확인할 항목
- 프로젝트 목적 / 주요 사용자 / 핵심 기능
- 일정 또는 기간 / 범위 및 제약사항 / 성공 기준

작동 예시

Turn 1Agent가 첫 질문
[체크리스트] - [ ] 1. 프로젝트 목적 - [ ] 2. 주요 사용자 - [ ] 3. 핵심 기능 - [ ] 4. 일정 또는 기간 - [ ] 5. 범위 및 제약사항 - [ ] 6. 성공 기준 먼저 이 프로젝트의 목적이 무엇인지 알려주실 수 있을까요?
User사용자 응답
"뉴스 RSS 피드를 받아와 최신 기사를 생성형 AI로 요약하고, 출처를 정리해주는 대시보드를 만들고 싶습니다."
Turn 2확인 + 다음 질문
목적을 "뉴스 RSS 피드를 AI로 요약하고 출처를 정리 하는 대시보드 개발"로 정리했습니다. [체크리스트] (1번 체크됨) 다음으로, 이 대시보드를 주로 사용할 사람들은 누구인가요?
UI Designer Prompt

UI Designer Prompt 구성

개발 스펙과 화면·기능 요구사항을 반영해 UI 화면을 설계하는 프롬프트 템플릿입니다.

prompt_template.md
아래 사용자 선택 및 입력된 내용을 바탕으로 UI를 설계하세요.
설계된 결과는 개발스펙에 맞는 code block으로 작성합니다.
개발환경에 따라 알맞은 파일구조도 함께 제시하세요.

- 개발환경 : {spec}
- Layout : {layout}
- 사용자입력 : {user_input}
- 추가요구사항: {others}
- 참조code: {reference}

5가지 변수

spec 단일 선택
개발 환경 — html/css/javascript 또는 python/streamlit (Streamlit은 되도록 파일 하나로 관리)
layout 복수 선택
사이드바 / 1단 메인 / 2단 메인 — 2단 선택 시 Streamlit이라면 st.columns(2) 활용
user_input 복수 선택
텍스트 입력 또는 ChatUI — ChatUI 선택 시 st.chat_message 기반 스트리밍 참조 코드 사용
others 여러 줄 입력
추가 기능·UI 요구사항 자유 기술 (최대 2만자)
reference 단일 선택
ChatAPIs / AgentAPIs / 없음 — 모델 호출 또는 에이전트 호출용 API 예제 코드 참조
Real Example

실제 PRD 예제 — 뉴스 AI 요약 대시보드

제품 개요

뉴스 RSS 피드를 자동으로 수집해 생성형 AI로 핵심 내용을 요약하고, 출처를 정리해주는 웹 기반 대시보드. 기업 내부 직원들이 최신 뉴스를 효율적으로 파악할 수 있게 돕습니다.

핵심 기능 (5개)
  1. 뉴스 수집 — RSS 피드에서 최신 뉴스 자동 수집
  2. AI 요약 — Gauss Chat API로 기사 내용 요약
  3. 출처 표시 — 원문 링크 및 출처 명시
  4. 검색 필터링 — 키워드 기반 뉴스 검색
  5. 대시보드 표시 — 요약된 뉴스를 화면에 표시
기술 스택

Python/Streamlit · Gauss Chat API · YNA RSS(yna.co.kr/rss/news.xml) · Python requests

비기능 요구사항 · 제외 범위

처리속도 5초 이내, 가용성 99% 이상 / 모든 뉴스 실시간 처리는 아님, YNA 외 RSS는 지원하지 않음

Key Points

핵심 포인트

🤖 PRD Agent 사용 시
  • 한 번에 1개만 질문
  • 체크리스트로 진행 상황 시각화
  • 확인한 내용 반복 질문 금지
  • 불명확한 내용은 추정 대신 확인
🎨 UI Designer Prompt 사용 시
  • 개발 환경 선택이 코드 생성의 핵심
  • 레이아웃은 복수 선택으로 조합 가능
  • API 참조 코드는 실제 구현에 필요
✅ 바이브코딩의 장점
  • 빠른 요구사항 정리 (자동 PRD 생성)
  • 프로토타입 신속 개발
  • 개발 환경 유연성
  • 아이디어→코드 자동화된 흐름
Conclusion

마치며

바이브코딩에서 PRD는 완벽한 문서가 아니라, AI가 정확히 참고할 수 있는 최소한의 기준입니다.

011~2페이지, 30분 이내로 작성하는 것이 목표입니다 — 완성도보다 명확성이 우선입니다.
02PRD Agent(요구사항 인터뷰) → UI Designer Prompt(화면 설계) 순서로 이어가면, 아이디어에서 프로토타입까지 하나의 흐름으로 완성됩니다.
