The Problem

기존 LLM Wiki의 딜레마 — 무차별적 지식 주입

안드레 카파시가 제시한 LLM Wiki는 훌륭한 도구입니다. 하지만 데이터를 '그냥 때려 박는(brute-force)' 방식은 치명적인 비효율을 낳습니다. 자료 Ingest → 에이전트가 모든 텍스트 처리 → 위키화 → 쿼리 응답이라는 흐름에서, 에이전트가 모든 전처리와 분석을 독점하는 것이 문제입니다.

1
100% 의존도
LLM 에이전트가 모든 문서를 직접 읽고, 구조를 파악하고, 연결성을 찾습니다.
2
유지보수(Linting) 비용
지속적인 가드닝과 중복 제거 작업 자체가 막대한 토큰을 계속 소모합니다.
3
확장 불가
지식 베이스가 커질수록 유지 비용이 기하급수적으로 증가합니다.
Architecture

Graphify의 아키텍처 — 하이브리드 전처리 엔진

지식을 통으로 넘기지 않습니다. 기계가 뼈대를 먼저 발라내고, AI는 정리만 수행합니다.

1
AST Extractor
Cost: $0 — raw text를 기계적으로 구조 분석
→
2
뼈대 / Skeleton
structural extraction — 에이전트가 소화하기 좋은 골격만 남김
→
3
서브 에이전트
GPT-4o-mini 등 경량 모델 — processed knowledge base 생성
⚙️ 0 토큰 전처리
  • LLM 대신 CS 이론인 AST를 적용해 지식 구조를 기계적으로 분석
🦴 뼈대 추출
  • 에이전트가 소화하기 가장 완벽한 형태로 데이터의 골격만 남김
⚡ 병렬 처리
  • 추출된 뼈대를 기반으로 서브 에이전트들이 빠르게 연관성을 매핑

Execution Playbook

실행 플레이북 — 4단계 구축 파이프라인

단 4단계의 명령어로 로컬 지식 베이스를 AST 기반의 그래프 네트워크로 변환합니다.

Node 1 · Initialize
환경 초기화
가상환경을 만들고 활성화한 뒤 Graphify 패키지를 설치합니다. UV 패키지 관리자로 빠르고 안전하게, 프로젝트 간 충돌 방지를 위해 항상 격리된 환경(빈 폴더)에서 시작합니다.
uv venv source .venv/bin/activate pip install [그래피파이 패키지]
Node 2 · Ingest
지식 주입
복잡한 서브 폴더 구조는 필요 없습니다. 프로젝트 루트에 notes 폴더 하나만 만들고, 기존에 쓰던 마크다운 문서들을 계층 구조 없이 그대로 복사해 넣으면 Graphify가 스스로 연결성을 찾아냅니다.
Node 3 · Graphify
지식 구조화
대상 폴더를 지정하면 AST 파싱 완료 → 서브 에이전트(GPT-4o-mini) 활성화 → 노드 병합 순으로 5~6분 내외 진행되며 지식 네트워크를 구축합니다.
$ graphify ./notes
Node 4 · Bind
에이전트 바인딩
맥락 제한(Context Locking) — 에이전트가 외부 지식이 아닌, 방금 생성된 내부 그래프 구조 안에서만 대답하도록 강제합니다. 할루시네이션 방지와 완벽하게 통제된 개인화 위키가 완성됩니다.
$ graphify codex install # 또는: $ graphify claude install
Outputs

산출물 — 지식 네트워크와 압도적인 비용 절감

🕸️ 시각적 지식 네트워크 (HTML Graph)

graphify_out 폴더에 생성되며, 지식들이 어떻게 연결되어 있는지 시각적으로 보여줍니다. Graph JSON·Report도 함께 생성되어 Obsidian 같은 외부 툴에 의존할 필요가 없어집니다.

💰 토큰 비용 절감 (ROI)

AST 전처리와 가벼운 서브 에이전트(GPT-4o-mini)의 조합으로, 동일한 양의 지식을 위키화할 때 약 5배의 토큰 비용을 절약합니다. 저렴한 API 요금제 사용자에게 완벽한 대안입니다.

The Future

개인 지식 관리(PKM)의 새로운 표준

무차별적 지식 주입의 시대는 끝났습니다. 토큰을 낭비하지 않는 기계적 전처리(AST)와 에이전트의 결합은 로컬 AI 지식 베이스가 나아가야 할 가장 우아하고 효율적인 해답입니다.

1세대
정적 폴더
(Static Folders)
2세대
의미론적 검색
(Semantic Search / RAG)
3세대 · 현재
그래프 최적화 AI 에이전트
(Graph-Optimized AI Agents)
Conclusion

결론

Graphify는 지식을 통으로 에이전트에게 던지는 대신, 기계가 뼈대를 잡고 AI가 다듬는 분업 구조로 LLM Wiki를 한 단계 진화시킵니다.

014단계(Initialize→Ingest→Graphify→Bind) 명령만으로 로컬 지식 베이스가 그래프 네트워크로 변환됩니다.
02맥락 제한(Context Locking)으로 에이전트가 오직 내 그래프 안에서만 답하게 만들어, 할루시네이션을 원천 차단합니다.
기억할 것 한 줄 — 지식 베이스가 커질수록, 문제는 AI의 똑똑함이 아니라 전처리 구조에 있습니다.
