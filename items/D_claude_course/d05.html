00 · Who & Why

이 강좌는 누구를 위한 것인가

Claude Code로 단발성 프롬프트는 이미 써본 개발자가, 더 길고 덜 감독하는, 팀 전체가 함께 쓰는 워크플로우로 넘어가기 위한 강좌입니다.

🎯 대상

  • Claude Code로 단일 프롬프트는 이미 써본 개발자
  • 더 길고 덜 감독받는 세션으로 넘어가고 싶은 사람

📋 선수 지식

  • 커맨드라인·git에 대한 기본 이해
  • Claude Code 접근 권한
  • Claude Code 기본기 실전 경험 권장

📦 구성

  • 9개 레슨, 약 1시간, 퀴즈 1회
  • 4개 축: 조율·설정·자동화·검증
핵심 문장 — 길고 손을 덜 대는 Claude Code 세션을 신뢰할 수 있게 운영하는 법을 배웁니다: 조율하고(steer), 설정하고(configure), 자동화하고(automate), 검증합니다(verify).
01 · Steer the Work

작업 조율하기

긴 세션에서도 방향을 잃지 않도록, Plan Mode·지시적 압축·되감기 메뉴·자율 실행 네 가지 도구로 작업을 조율합니다.

Tool 01
Plan Mode

구현 전에 범위를 먼저 정의. 파일 편집 없이 접근 방식만 세워 코드가 쓰이기 전에 방향을 검토합니다.

Tool 02
지시적 압축(Directed Compaction)

세션이 길어질 때 무엇을 요약에 남길지 직접 지정해, 중요한 맥락이 압축 과정에서 사라지지 않게 합니다.

Tool 03
되감기(Rewind) 메뉴

궤도를 벗어났을 때 이전 지점으로 되돌아가 다시 방향을 잡습니다. 처음부터 다시 시작할 필요가 없습니다.

Tool 04
Goal & Loop 실행

손으로 직접 조율할지, 아니면 목표만 주고 자율적으로 반복 실행하게 할지 작업 성격에 맞게 선택합니다.

고급 실행 — 자율·병렬 작업은 목표(goals)와 루프(loops), 그리고 git worktree를 함께 활용해 여러 작업을 동시에, 서로 간섭 없이 진행할 수 있습니다.
02 · Configure Claude

Claude 설정하기

CLAUDE.md는 강제되는 설정이 아니라 안내입니다. 모든 줄이 서로의 주목도를 두고 경쟁하기 때문에, 파일이 길어질수록 각 규칙이 지켜질 확률은 낮아집니다.

린(lean)한 CLAUDE.md
정당화할 수 없는 줄은 삭제합니다. 하드 룰은 훅으로 옮기고, 긴 파일은 @경로 import로 정리하되 — import는 실행 시 그 자리에 그대로 펼쳐지므로 컨텍스트를 줄여주지 않는다는 점에 유의합니다.
Skills (스킬)
반복되는 절차를 패키징해 적절한 작업에 자동으로 적용되는 재사용 가능한 마크다운 지침으로 만듭니다.
6가지 권한 모드
작업마다 필요한 자율성 수준에 맞춰 권한 모드를 매칭합니다 — 매번 승인부터 완전 자율까지.
Hooks (훅)
Claude의 행동을 허용·거부·재작성함으로써 확률적 "부탁"이 아니라 확정적 "규칙"으로 강제합니다.
# CLAUDE.md를 린하게 유지하는 원칙
1. 프로덕션 코드처럼 다룬다 — 정당화 안 되는 줄은 삭제
2. 하드 룰 → 훅으로 이전 (실제로 강제됨)
3. 모든 규칙을 구체적이고 체크 가능하게, 대안까지 명시
4. Claude가 뭔가 틀릴 때마다 파일을 계속 수정
03 · Automate Repeat Work

반복 작업 자동화하기

한 번 검증한 흐름은 사람 없이도 돌아가도록 Anthropic 인프라의 루틴, 헤드리스 모드, GitHub Action으로 확장합니다.

Cloud Routines

예약 루틴

Anthropic 인프라에서 프롬프트를 정해진 시간에 자동 실행하는 루틴으로 예약합니다.

Headless Mode

헤드리스 모드

작업이 나만의 파이프라인에 맞춰져야 할 때, UI 없이 스크립트·CI에서 Claude Code를 호출합니다.

GitHub Action

PR 연동

GitHub Action과 매니지드 코드 리뷰로 Claude를 풀 리퀘스트 흐름에 직접 연결합니다.

매일 아침 자동 생성되는 리포트 CI/CD 파이프라인 속 코드 점검 PR이 열릴 때마다 자동 리뷰
04 · Verify & Share

검증하고 팀과 공유하기

사람이 덜 지켜볼수록, 그만큼 검증은 더 철저해야 합니다. 검증을 스킬로 만들고, 훅으로 강제하고, 신뢰할 수 있는 설정을 팀 전체가 쓸 수 있는 플러그인으로 패키징합니다.

Verification Skill

검증 스킬

테스트를 실행하고, diff를 읽고, 증거를 자동으로 보고하는 검증 스킬을 만듭니다. 감독을 덜 받은 실행일수록 이 검증에 더 크게 의존합니다.

Hooks + 테스트 결과

게이트(gate)

다음 턴으로 넘어가기 전에 실제 테스트 결과를 기준으로 진행을 막거나 허용하도록 훅을 겁니다.

Plugin 패키징

팀 배포

CLAUDE.md·스킬·훅·권한 모드까지 검증이 끝난 설정을 플러그인 하나로 묶어 팀 전체가 설치할 수 있게 합니다.

원칙 — "지켜본 만큼만 검증한다"가 아니라 "지켜보지 않은 만큼 검증한다"가 이 구간의 핵심 태도입니다. 자율 실행이 늘어날수록 검증의 엄격함도 함께 늘어나야 합니다.
Conclusion

마치며

Claude Code in Action은 "믿고 맡길 수 있는 긴 세션"을 만드는 강좌입니다. 짧은 프롬프트 하나를 잘 쓰는 것과, 팀 전체가 덜 감독하며 반복 가능한 워크플로우를 굴리는 것은 다른 스킬입니다.

01Plan Mode로 범위를 정하고, 필요하면 되감기로 궤도를 수정하며, 작업 성격에 맞게 손으로 조율할지 자율 실행에 맡길지 선택하세요.
02CLAUDE.md는 린하게 유지하고 하드 룰은 훅으로, 반복 절차는 스킬로 옮기세요.
03검증한 흐름은 루틴·헤드리스·GitHub Action으로 자동화하고, 지켜보지 않은 만큼 검증을 강화한 뒤 플러그인으로 팀에 공유하세요.
다음 단계 — 최근 자주 반복했던 Claude Code 작업 하나를 골라, CLAUDE.md 다이어트 → 훅 하나 추가 → 스킬로 패키징까지 한 번에 해보세요. 설정이 손에 붙는 가장 빠른 길입니다.
