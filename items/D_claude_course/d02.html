01 · Overview

Claude Code란 무엇인가

Claude Code는 여러분의 코드베이스를 이해하고, 파일을 수정하고, 명령을 실행하며, 기존 개발 도구와 통합되는 에이전틱 코딩 도구입니다. Claude.ai와 달리 파일·터미널·코드베이스 전체에 직접 접근합니다.

🤖 채팅형 AI와 다른 점

  • 코드를 복사·붙여넣기 하는 대신 직접 들어가 작업
  • 파일·터미널·전체 코드베이스에 직접 접근
  • 사람 손을 자유롭게, 원하는 만큼 개입 가능

🚪 어디서 쓰나

  • 터미널 (기본 인터페이스)
  • VS Code · JetBrains IDE 확장
  • Claude Desktop 앱, 웹

🎯 대상

  • 소프트웨어 개발이 처음인 사람
  • AI 코딩 에이전트를 아직 안 써본 숙련 엔지니어
  • 코드 편집기·커맨드라인 기본 사용법만 알면 충분
포인트 — 버그를 코드베이스 전체에서 추적하거나, 새 서비스를 스캐폴딩하거나, PR을 한 무더기 리뷰하는 것처럼 예전엔 하루가 걸리던 일이, 코드를 읽고 명령을 실행하고 함께 파일을 편집하는 에이전트 덕분에 한 번의 집중 세션으로 끝날 수 있습니다.
02 · How It Works

작동 원리 — 에이전틱 루프

Claude Code는 에이전틱 루프, 컨텍스트 윈도우, 도구, 권한 — 네 가지 개념의 조합으로 설명됩니다. 이 네 가지를 이해하면 이후 배우는 모든 기법이 암기가 아니라 이해로 다가옵니다.

STEP 01
프롬프트 입력
사용자가 터미널에 요청을 입력
→
STEP 02
컨텍스트 수집
모델과 상호작용하며 필요한 정보를 모으고, 텍스트 또는 도구 호출을 반환
→
STEP 03
행동 & 검증
파일 수정·명령 실행 등 행동을 취하고, 목표 달성 여부를 스스로 확인
→
STEP 04
종료 또는 반복
완료됐으면 다음 프롬프트 대기, 아니면 루프를 반복
컨텍스트 윈도우
대화·파일 내용·명령 출력 등을 저장·참조할 수 있는 한정된 용량. 한도에 도달하면 대화를 압축(compact)해 다시 사용 가능한 크기로 줄입니다.
도구 (Tools)
Claude가 파일을 읽고 쓰고, 검색하고, 명령을 실행하기 위해 사용하는 능력들입니다.
권한 (Permissions)
내 컴퓨터에서 무슨 일이 벌어질지 사용자가 계속 통제할 수 있도록 하는 승인 체계입니다. Claude는 기본적으로 행동 전에 허락을 구합니다.
세 가지 기본 원칙 — ① 컨텍스트 윈도우는 유한하다 ② Claude는 기본적으로 허락을 구한다 ③ Claude도 실수할 수 있으므로 계속 관여하는 것은 선택이 아니라 필수입니다.
03 · Installation

설치 및 환경 설정

이미 작업하고 있는 환경 어디에서든 Claude Code를 그대로 사용할 수 있습니다 — 터미널, VS Code나 JetBrains 안, Claude Desktop, 또는 웹.

Default

터미널

가장 기본적인 인터페이스. 어떤 프로젝트 폴더에서든 claude 명령으로 시작.

IDE 확장

VS Code · JetBrains

에디터 안에 사이드 패널로 통합되어, 파일을 오가며 바로 대화하고 diff를 확인.

GUI

Claude Desktop

데스크톱 앱의 Code 탭에서 GUI로 동일한 에이전트를 사용.

Remote

웹

브라우저에서 원격 세션으로 실행, 로컬 환경 없이도 접근 가능.

이미 쓰는 에디터·터미널 그대로 사용 환경을 바꾸지 않고 워크플로우에 편입 어디서 설치하든 핵심 기능은 동일
04 · Prompting

효과적인 프롬프트 작성 — 3가지 모드

같은 요청이라도 어떤 모드로 진행하느냐에 따라 Claude가 얼마나 자율적으로 움직이는지가 달라집니다. 확률적으로 동작하는 프롬프트와 달리, 상황에 맞는 모드 선택이 결과를 좌우합니다.

Manual

수동 승인

파일 수정·명령 실행 등 행동 하나하나마다 사용자 승인을 요구. 처음 쓰거나 민감한 작업에 적합.

Auto-Accept

자동 승인

Claude가 계획한 편집을 매번 묻지 않고 바로 적용. 신뢰할 수 있는 반복 작업에서 속도를 높임.

Plan Mode

계획 모드 (Shift+Tab)

Claude가 파일을 편집하지 못하고 읽기만 하며 접근 방식을 조사·제안. 코드가 쓰이기 전에 궤도를 수정할 수 있는 최적의 지점.

선택 가이드 — 새로운 기능이나 복잡한 변경은 Plan Mode로 시작해 방향을 먼저 검토 → 승인 후 Manual이나 Auto-Accept로 실제 구현을 진행하는 흐름이 가장 안전합니다.
05 · Core Workflow

Explore → Plan → Code → Commit

이 강좌에서 단 하나만 기억해야 한다면 바로 이 워크플로우입니다. 이 흐름 없이 곧바로 "코드를 짜줘"라고 요청하면, 나중에 더 많은 궤도 수정이 필요해집니다.

STAGE 01
Explore
Claude가 프로젝트의 관련 부분을 읽고 이해를 쌓도록 함
→
STAGE 02
Plan
구현 전에 논쟁하고 검토할 수 있는 문서화된 접근 방식을 확보 (Plan Mode 활용)
→
STAGE 03
Code
계획을 실행 — 최종 결과가 나올 때까지 Claude와 주고받는 반복
→
STAGE 04
Commit
코드를 검토하고 커밋 메시지를 생성해 깔끔하게 반영, 다음 작업으로
# Plan Mode 진입: Shift + Tab (입력창 아래 "Plan Mode" 표시 확인)
> 이미지 업로드 파이프라인에 WebP 변환을 추가해야 해.
  파이프라인 어디에 넣어야 할지, 새 의존성이 필요한지,
  어떻게 접근할지 파악해줘.
실무 팁 — Plan Mode에서는 파일을 읽기만 하고 편집하지 않으므로, 코드가 쓰이기 전 가장 안전하게 궤도를 수정할 수 있는 지점입니다. 계획이 만족스러우면 "approve"로 승인해 목록을 실행시키고, 완료 후 Claude에게 내 스타일의 커밋 메시지 생성을 맡길 수 있습니다.
06 · Context Management

컨텍스트 관리 — /compact · /clear · /context

긴 세션일수록 컨텍스트 윈도우가 채워지며 성능·정확도·생산성이 떨어질 수 있습니다. 세 가지 명령으로 세션을 계속 생산적인 상태로 유지합니다.

/compact
현재 대화에서 무엇을 줄이고 요약할지 Claude가 자동으로 판단해, 컨텍스트 윈도우를 다시 쓸 만한 크기로 되돌립니다. 한도에 다다르면 자동으로도 실행됩니다.
/clear
대화 히스토리를 완전히 비우고 새로 시작합니다. 이전 작업과 무관한 새 작업으로 넘어갈 때 유용합니다.
/context
현재 컨텍스트 윈도우에 무엇이 얼마나 차 있는지 확인해, 압축·정리 시점을 스스로 판단할 수 있게 합니다.
왜 중요한가 — "왜 Claude가 20분 전에 얘기한 걸 잊어버렸지?"라는 혼란은 대부분 컨텍스트 윈도우가 꽉 찼거나 자동 압축된 결과입니다. 세 명령을 능숙하게 다루면 긴 세션에서도 정확도와 비용 효율을 함께 지킬 수 있습니다.
07 · Code Review

Claude Code로 코드 리뷰하기

코드를 작성하는 것만큼이나, 변경 사항을 검토하는 것도 워크플로우의 핵심입니다. Claude Code는 자신의 변경분이든 다른 사람의 PR이든 리뷰를 도울 수 있습니다.

Diff 확인

변경분 검토

현재 세션에서 만들어진 변경 내역을 살펴보고, 의도한 대로인지 단계별로 확인합니다.

읽기 전용 리뷰

더 깊은 검토

파일을 수정하지 않고 정확성·정리 상태를 점검하는 심층 리뷰를 요청할 수 있습니다.

보안 리뷰

위험 요소 점검

대기 중인 변경 사항에 보안 위험이 있는지 별도로 점검하도록 요청합니다.

실무 예 — PR을 올리기 전, Claude에게 "이 diff를 리뷰해줘, 엣지 케이스와 네이밍 컨벤션을 확인해줘"처럼 요청하면 사람이 보기 전에 명백한 문제를 먼저 걸러낼 수 있습니다.
08 · Make It Yours

나만의 Claude Code 만들기

강좌의 마지막 구간은 Claude Code를 내 프로젝트·팀에 맞게 커스터마이징하는 다섯 가지 방법을 다룹니다.

📄 CLAUDE.md

  • 프로젝트의 컨벤션·규칙을 기록해두는 파일
  • 세션이 바뀌어도 Claude가 계속 기억하게 함

🧩 서브에이전트 (Subagents)

  • 특정 작업을 위임할 별도 에이전트 구성
  • 메인 컨텍스트를 깨끗하게 유지

🛠️ Skills

  • 자주 반복하는 작업을 재사용 가능한 절차로 저장
  • 필요할 때 Claude가 스스로 불러 사용

🔌 MCP 서버

  • 외부 도구·데이터 소스에 연결
  • 생태계에서 가장 비중 있게 다뤄지는 주제 중 하나

🪝 Hooks

  • 매 편집 후 자동 포맷팅, 특정 명령 차단, 작업 완료 알림
  • "부탁"이 아니라 규칙 — 확률적 프롬프트와 달리 항상 보장됨
다섯 표면의 관계 — CLAUDE.md는 무엇을 기억할지, Subagents·Skills는 무엇을 어떻게 위임·재사용할지, MCP는 어디에 연결할지, Hooks는 무엇을 반드시 지키게 할지를 각각 담당합니다. 다섯 가지를 조합하면 팀 전체가 동일한 방식으로 Claude Code를 쓰게 됩니다.
Conclusion

마치며

Claude Code는 "코드베이스 안에서 직접 일하는 에이전트"입니다. 도구를 설치하는 것과 잘 쓰는 것 사이에는, 에이전트가 어떻게 사고하고 어떤 컨텍스트에 접근하며 궤도를 어떻게 수정하는지에 대한 이해가 필요합니다.
